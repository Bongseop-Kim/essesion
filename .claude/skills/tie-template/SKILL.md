# 넥타이 템플릿 만들기

스토어 `/design`의 템플릿은 **시드 코드가 정본**이다(DB가 아니다). 사용자가 넥타이 샘플 이미지를 주면
그 느낌을 엔진 플랜으로 옮기고, 결과 이미지를 보며 사용자와 함께 고친다.

## 스스로 학습 (사용자가 시키지 않아도 한다)

이 스킬은 쓰일 때마다 자란다. 사용자가 "스킬 업데이트해"라고 말하기를 기다리지 말고, 아래 신호가
오면 **그 자리에서** 이 문서(`.claude/skills/tie-template/SKILL.md`)를 직접 고친다.

- **언제**
  - 사용자가 결과를 고치라고 했다("아니야", "너무 커", "더 오른쪽") → 무엇이 틀렸고 무엇이 맞았는지.
  - 사용자가 방향을 정해 줬다(AskUserQuestion 답 포함) → 다음엔 다시 묻지 않을 기본값.
  - 작업 중 함정·버그를 밟았다(실패한 명령, 엉뚱한 렌더, 엔진 제약) → 피하는 법.
  - 사용자가 결과를 그대로 받아들였다 → 통한 방식(수치·색·밀도)을 기준값으로.
- **어디에** — 맨 끝에 덧붙이기만 하지 말고 그 지식이 쓰일 절(제약·로고·단계)을 고친다. 일반화된
  교훈은 "배운 것"에 날짜와 함께 한 줄, 그리고 "변경 이력"에 한 줄.
- **어떻게** — 짧게, 규칙 형태로("X 하지 말 것 — 이유"). 이미 있는 항목과 겹치면 합치고, 틀린 것으로
  드러난 항목은 지운다. 문서와 코드가 어긋나면 코드를 믿고 문서를 고친다.
- **안 적을 것** — 템플릿 하나에만 해당하는 일회성 취향, 추측, 아직 확인 안 된 가설.
- **알리기** — 고친 뒤 응답 끝에 "스킬 갱신: …" 한 줄로 무엇을 바꿨는지 사용자에게 알린다.

## 진행 방식 — 사용자와 토의하며

1. **참조 해석을 먼저 말한다.** 이미지를 보고 템플릿마다 바탕색·무늬 구조(스트라이프 방향·묶음, 격자·
   엇갈림)·로고 모양·카테고리, 그리고 **반복형/배치형** 구분을 짧은 표로 정리해 보여준다. 엔진으로 못 하는 부분(아래 제약)은
   이때 미리 말한다.
2. **사용자 몫의 결정은 묻는다.** 재현 방식이 갈리는 지점(예: 단일 로고를 어떻게 다룰지)은
   AskUserQuestion으로 권장안을 첫 번째에 둔다. 이미 "배운 것"에 답이 있으면 다시 묻지 않는다.
3. **설계 → 렌더 → 비교 반복.** 템플릿마다 `cand.py`를 쓰고 `render.py`로 그려 참조와 나란히 본다.
   여러 개면 템플릿 하나당 서브에이전트 하나(아래 "병렬 작업").
4. **병합 → 시드 → 스토어 확인.** 결과를 실제 카드로 보고, 사용자에게 스크린샷으로 보고한다.
5. **피드백을 받으면 고치고 다시 본다.** 위치·크기·밀도 같은 미세 조정은 숫자를 바꿀 때마다
   스크린샷으로 확인하고, 피드백에서 배운 것은 바로 이 문서에 반영한다("스스로 학습").

## 엔진 제약 (설계 전에 반드시)

- 플랜 모티프는 **최대 2개**, 레이어 **최대 5개**, 스트라이프 레이어당 밴드 **최대 4개**(같은
  주기 레이어를 둘로 나누면 된다). 같은 모티프를 여러 레이어에서 재사용할 수 있다.
- **모티프 색은 바꿀 수 없다** — SVG에 칠한 색 그대로다. 사용자가 고를 수 있는 색은 플랜 `colors`
  (바탕·스트라이프)뿐이고, `color_names`에 이름 붙인 슬롯만 색 고르기 화면에 나온다.
  `colors`는 최소 2개라 안 쓰는 색을 자리만 채우기도 한다(그 슬롯엔 이름을 붙이지 않는다).
- 무늬는 타일 단위 seamless 반복. lattice 원점은 (0,0) 고정이고 오프셋이 없다 — 위치 조절은
  `drop`(half_row/half_column), `point_template`(quincunx_inset·diagonal_pair·grid4_inset),
  스트라이프 `offset_ratio`로 한다.
- 사선 주기는 타일과 맞물려야 이음매가 없다: `period_ratio = 1/(k·√2)` (k=1 0.70710678,
  k=2 0.35355339, k=3 0.23570226, k=4 0.1767767).
- **사선 스트라이프는 무조건 우상향(/) = `diagonal_up`.** 넥타이에 좌상향(\\, `diagonal_down`) 줄무늬는
  없다(2026-10-16 사용자 규칙). `diagonal_down`은 양방향을 겹치는 격자·다이아 체크에서만 쓴다.
- **path 한 레이어 = 레인 한 줄**: 사선 직선 경로는 타일당 닫힌 선 하나(x+y ≡ 상수)만 돈다. 사선 k개
  틈을 다 채우려면 틈마다 경로 레이어가 하나씩 든다(틈 0은 호스트 없는 원점 경로, 나머지는 k=1 바탕색
  레인 스트라이프의 밴드 `j/k`). 레이어 5개 상한이라 핀 줄 + 레인 + 경로 3 = **틈 3줄(k=3)까지**.
- **path `phase_ratio`는 감기지 않는다** — 시작점부터 경로 끝까지만 놓으므로 phase ≥ spacing이면 개수가
  줄어든다. phase는 spacing 미만으로 줄여 적는다(2026-10-17, 고리 9개가 5개로 줄었다).
- 타일 크기는 `CuratedExample.tile_scale`(기본 1.0, 48mm 배율) — `render.py`는 cand의 `TILE_SCALE`.
- 점선·체인처럼 줄 위에 얹는 무늬는 바탕색 스트라이프를 lane으로 깔고 `path` 배치(`host_stripe_index`
  ·`host_band_index`)로 모티프를 얹는다. 모티프 가로세로 비는 최대 20(normalize 한도).
- **배치형(한 번만 놓이는) 무늬는 panel로 만든다** — 대각·V 분할, 한쪽 곡선 띠, 한쪽 세로선, 넝쿨 가지,
  붓 터치. 큰 타일(tile_mm 확대)로 흉내 내지 말 것: 긴 실사 컷에서 반복된다(2026-10-16 사용자 기각).
  `CuratedExample.panel`에 intent `panel` 요소(region·line·curve_band·motif)를 적는다 — 계약은
  `docs/api-spec/worker-engine.md` §2b. 아래 "배치형(panel)" 절.
- `vertical` 스트라이프의 `offset_ratio`는 **오른쪽 가장자리에서** 잰다 — 화면 순서(왼→오)의 반대로 적는다.
  `horizontal`은 **위에서** 잰다(타일 y와 같은 방향) — offset을 키우면 줄이 내려간다(2026-10-17 가로 바 확인).
- **격자 한 자리를 로고로 바꾸기**: 로고 레이어를 **먼저** 두고, 점 레이어에 `avoid_motif_layer`(로고
  레이어의 모티프 레이어 서수, 0부터)를 준다 — 점이 로고와 겹치는 자리만 빠진다(외접원 근사,
  반경 `(로고 size + 점 size)/2`). 로고는 점 자리 위에 떨어지는 어떤 배치(sateen 등)든 된다.
  avoid 이전의 우회(같은 자리를 여러 레이어로 나눠 깔고 그중 하나를 로고로: 2×2 lattice = 짝수 행,
  `diagonal_pair` = (¼,¼)(¾,¾), `diagonal_up` path spacing 0.5·phase 0.25 = (¼,¾)(¾,¼))는 로고가
  규칙적 자리에만 가므로 이제 쓸 이유가 없다.
- 1×1 lattice는 타일 원점 (0,0)에 놓인다. 다른 격자와 원점이 겹치면 로고를 `path` straight
  `horizontal` + `phase_ratio`(예 0.25)로 옮겨 빈자리에 둔다(lattice엔 오프셋이 없다).
- 호스트 없는 wave path는 타일당 y=0 한 줄뿐이고 phase는 경로 방향이라 줄 간격을 못 만든다. 연속
  물결선은 "한 파장 폭 물결 조각" 모티프를 lattice로 이어 붙인다(size를 셀보다 0.3% 크게 → 접합 헤어라인 없음).
  파장은 타일의 1/정수(size ≤ 0.4라 최대 1/3)에 묶인다.
- 밀도: 평면 카드에서 넥타이 폭 ≈ 1.5타일. 넥타이 폭에 무늬 2~4개가 기본.
- **타일 렌더로 판단을 끝내지 말 것** — 2×2 타일에서 괜찮던 것이 카드 넥타이 크기에선 달라진다.
  k=2 사선의 블록 띠는 가는 줄처럼 보이고(굵은 블록은 k=1), 크기 0.1 미만 모티프는 점·x로 뭉개진다.
  크기·굵기 판단은 반드시 스토어 카드 스크린샷(deviceScaleFactor=2 확대 크롭)으로.

## 구조 팔레트 — 같은 계열 템플릿끼리 겹치지 않게

같은 카테고리(특히 스트라이프)를 여러 개 만들 땐 아래에서 **서로 다른 구조**를 고른다. 방향·색만
바꾼 "사선 묶음 + 작은 로고"를 반복하지 말 것(2026-10-16 사용자 피드백: 다양성 부족).

| 구조 | 엔진 표현 | 예 |
|---|---|---|
| 렙(rep) 스트라이프 | 촘촘한 사선 k=3(`diagonal_up`), 굵은 띠를 가는 줄이 감쌈. 색은 원색 말고 크림슨·아이보리, 로고는 panel 방패 문장 | 흰 줄과 빨간 줄 렙 스트라이프 |
| 스트라이프 + 모티프 행 | 바탕색 레인 밴드 + `path` straight(`host_band_index`, `rotation: fixed`)로 모티프가 줄지어 흐름 | 잎 가지가 흐르는 사선 |
| 블록 스트라이프 | k=1, 밴드 폭 ~0.45로 두 톤 굵은 띠 반반 + 경계 가는 줄, 로고는 `diagonal_pair`로 띠 중앙 | 블록 스트라이프와 물결 엠블럼 |
| 가로 바 | `horizontal` period 0.5 바 + 바탕색 레인(period 1.0 두 밴드) 위 가로 path 두 행(phase 엇갈림, spacing 1.0) — 격자 행은 y=0·½ 고정이라 바 사이 한가운데에 못 맞춘다. 레인 위상으로 끝 로고도 바 사이 칸에 | 가로 바와 날개 엠블럼 |
| 클래식 사선 묶음 | k=2 가는 줄 묶음 + 사이 로고 2×2 바둑판(엇갈림은 블록 스트라이프 몫) | 핀 스트라이프와 세 고리 |
| 사선 점선·체인 | 바탕색 lane + 점선 모티프·로고를 path로 엇갈림 | 모노그램 사선 점선 |
| 다이아 체크 | 양 사선 반폭 밴드 두 겹 + 겹침 칸 마름모 모티프 | 다이아 체크와 세리프 이니셜 |
| 잔 격자 + 포인트 | 양 사선 가는 밴드(k=2~4) + 칸 중앙 모티프 | 육각 엠블럼과 꽃문양, 마름모 격자와 네이비 꽃 |
| 올오버 엇갈림 | lattice `half_row`/`half_column`, `quincunx_inset` | 나무·큐브 템플릿 |
| 올오버 45° 사슬 | 로고 sateen 12·5 + 점 `diagonal_up` 경로 두 레인(중점) | 로고 하프드롭과 점 |
| 도트 | 타일 2배, 로고 sateen order 8·step 3(점 자리 위, 세로·가로 일직선 없음) + 점 lattice 4×4 + `grid4_inset`(합쳐 하프로우 전체), 두 점 레이어에 `avoid_motif_layer: 0`. 점 사이 빈칸에 끼우면 점 넷에 갇힌다 | 세리프 R과 마름모 도트 |
| 세로 스트라이프 + 포인트 로고만 | `vertical` period 1.0, 밴드 4+1(레이어 둘), offset은 오른쪽 기준. 무늬 모티프 없이 `panel=({**PANEL_LOGO, …},)`, 묶음 위상은 로고 자리를 비우게 | 세로 스트라이프와 세리프 V |
| 윈도페인 체크 | 양 사선 가는 줄 한 밴드(offset 0.5, k=2), 칸 속 문장은 `diagonal_pair` 엇갈림(1×1은 세로 두 줄로만 박혀 단조) | 윈도페인 체크와 십자 문장 |
| 톤온톤 물결선 | 한 파장 물결 조각 lattice 3×2(size 0.3345), 바탕보다 한 톤 밝은 모티프 색, 작은 로고는 틈에 `diagonal_pair` 엇갈림 | 물결선과 물결 원 엠블럼 |

| 배치형 사선 분할 | panel `region`(아래 면) + `line`(경계 한 줄) | 사선 분할과 세리프 A |
| 배치형 세로 금선 | panel `line` 여러 개, 위(y=-4600)에서 내려와 `end_dot`으로 끝 | 세로 금선과 막대 로고 |
| 배치형 곡선 겹띠 | panel `curve_band` 같은 중심선을 x로 밀어 2~3겹 | 곡선 띠와 네잎 로고 |
| 배치형 V자 분할 | panel `region` + 두 팔 `line` + 한쪽 팔 굵은 띠 | V자 분할과 큐브 로고 |
| 배치형 큰 모티프 | panel `motif`(decor) 큰 size로 한 번 — 넝쿨 가지·붓 터치 | 넝쿨 가지와 C 로고, 붓 터치와 세리프 N |

## 배치형(panel)

- **좌표 = 블레이드 프레임(등방)**: x 0..1000 = 어깨 폭, y는 같은 단위로 어깨선 1000·끝 ≈1500. 평면
  카드는 y ≈ 210..1500만 보이고, 실사 컷은 y ≈ -4400(매듭 아래)까지 보인다. 위에서 내려오는 선·띠는
  y=-4600부터 시작해야 실사 컷에서 중간에 끊기지 않는다.
- **바탕 플랜은 `_textured_plan`**(바탕 + 한 톤 밝은 가는 사선 결). 결 슬롯에도 이름(`결`)을 붙인다 —
  바탕만 바꾸면 결 색이 따로 놀아 줄무늬가 드러난다.
- **사선 panel 선·경계는 결과 같은 45°(dx = dy)로** — 결(`diagonal_up`, 다이아 결은 양방향)이 45°라
  각도가 조금만 달라도 선과 잔선이 어긋나 보인다(2026-10-17 사용자 지적: 사선 분할 38°, V 오른팔 57°).
- **굵은 띠가 꼭짓점·다른 선에서 끝나면 `line` 말고 `region`으로** — line 끝은 띠에 수직으로 잘려 덜 만든
  단면이 남는다. region으로 상대 선에 맞물리게(마이터) 자른다(2026-10-17, V자 분할 와인 띠).
- **곡선 띠는 굽이마다 베지어 한 조각, 이음점의 앞뒤 제어점은 한 직선 위, 겹띠는 법선 평행
  오프셋으로** — 제어점이 어긋나면 이음점에서 꺾여 보이고, x로만 밀면 누운 구간에서 띠가 가늘어진다.
  굽이를 하나로 줄여 매끄럽게 만들지는 말 것 — 두 번 꺾이는 S자가 더 매력 있다는 사용자 판단
  (2026-10-17, `_bellen_band` 참고).
- **포인트 로고는 `{**PANEL_LOGO, "subject": …}`**(어깨선 위 오른쪽, 면적 기준). `point="bottom"`,
  `logo_slots=(("logo", "포인트 로고"),)` — 로고 넣기는 panel 로고 자리(`slot="logo"`)로 가고, 카드 엠블럼 오버레이는
  `logo_in_panel`이라 그리지 않는다.
- 색은 슬롯 id(`ground`·`color_<i>`, 플랜 colors 순서)로 적는다. panel 모티프는 `subject`로 적고 시드가
  motif_id로 푼다. `render.py`는 panel을 모르므로 panel 위치는 시드 후 store 화면(목록 flat·상세 photo
  실루엣, 5단계)에서 두 실루엣의 위치가 같은지 본다.

## 로고 (포인트 로고 + 무늬 속 로고)

- 참조의 큰 로고 하나는 `point="bottom"`(카드가 블레이드 아래쪽에 엠블럼을 얹는다)이고, 엠블럼은
  `logo_slots` 자리의 모티프다. 엔진상 로고 슬롯 모티프는 **무늬 레이어에도 반드시 있어야** 해서 작고 성기게
  반복시킨다(2026-10-16 사용자 결정).
  단, 작은 로고 반복이 큰 로고와 붙어 산만하면 반복형이라도 무늬 모티프를 빼고 panel 로고 하나만
  둔다(`motifs: []`, 자리는 `"logo"` 하나) — 그리고 무늬 위상을 밀어 로고 자리를 바탕으로 비운다
  (2026-10-17 세로 스트라이프와 세리프 V). 테스트의 배치형 개수(`len(placed)`)도 함께 고친다.
- **`logo_slots`의 숫자 자리는 레이어 순서다.** 플랜 input 순서가 아니라 intent 모티프 레이어를 그리는 순서의
  고유 id 인덱스(api `_intent_motif_ids`). 장식 레이어를 먼저 그리면 로고 자리는 `2`.
  병합 후 `check_emblems.py`로 모든 행의 subject가 로고인지 확인한다.
- 로고 자리 모티프는 참조 로고의 심볼을 손으로 그린 path(`<text>` 금지). 바탕 위에서 보이는
  아이보리·실버·금 계열. subject는 영문 한 단어, **기존 seed subject와 겹치면 안 된다** — 시드는
  subject로 모티프를 고른다(`select distinct subject from motifs where source='seed'`).
  `_SEEDS`에 없어도 `motif_assets/*.svg` 글리프(파일명 첫 토큰이 subject, 예 `shield`)가 시드에 있다 —
  코드 grep 말고 반드시 이 DB 쿼리로 확인(2026-10-17 `shield` 충돌로 검은 윤곽 방패가 떴다 → `crest`).
  모티프 id는 SVG 내용이라 subject만 바꾸면 같은 행이다 — `seed_motifs.py`가 subject도 재기록한다.
- **포인트 로고 배치는 로고마다 다르다.** `TieCanvas`가 로고 실제 외곽(getBBox)을 재서 같은 면적
  (`size`)으로 키우고 `maxW`·`maxH`로 자른 뒤 `anchor` 점에 붙인다. 끝 로고는 `bottom-right` —
  오른쪽 여백과 바닥선이 같고, 넓은 로고는 왼쪽·높은 로고는 위로 자란다. 위치를 바꿀 땐 템플릿이
  아니라 `SILHOUETTES[*].emblem.tip`의 anchor·size를 바꾸고 flat(목록)·photo(상세) 둘 다 본다.

## 단계별 실행

### 1. 후보 설계·렌더

작업 폴더는 scratchpad 아래 `tpl/<NN>/`. `cand.py`에 `PLAN`(dict)과 `MOTIFS`를 정의하고:

```bash
uv run python .claude/skills/tie-template/scripts/render.py <cand.py> <out_prefix>
```

`<out_prefix>_2x2.png`를 Read로 보고 참조와 비교한다. `warnings`가 비어야 한다. 이음매·겹침·밀도·색.

### 2. 병렬 작업 (템플릿 여러 개)

템플릿 하나당 서브에이전트 하나. 공통 브리프 파일을 scratchpad에 쓰고 각자에게 번호와 묘사만 준다.
브리프에 넣을 것: 이 문서의 "엔진 제약"·"로고" 절, **레포 파일·DB 수정 금지(시드 실행 금지)**,
결과는 코드 조각으로 반환(PLAN 상수·CuratedExample·`_SEEDS` 튜플·
최종 렌더 경로·참조와 다른 점). 병합은 메인이 한 번에 한다 — 같은 파일 동시 편집·시드 충돌 방지.

### 3. 병합

- 플랜 상수는 `# 스토어 템플릿 목록` 앞에, `CuratedExample`은 `CURATED` 끝에, 모티프는 `_SEEDS` 끝에.
- 주석은 기존처럼 한두 줄 한글. ruff 줄 길이 100(한글 주석이 자주 넘는다).
- 템플릿 이름·설명은 한글 서술형, 브랜드명 금지. `category`는 목록 필터 칩 라벨 그대로.

## 배운 것 (사용자 피드백·함정)

- **밀도**: 첫 시도는 늘 너무 촘촘했다. 넥타이 폭에 로고 2~3개가 참조 느낌(2026-10-15).
- **색**: 원색 코발트는 싸 보인다 — 한 톤 깊게(`#2451b5`→`#1d3a80`). 검정 아이콘 모티프는 네이비에서
  안 보이니 템플릿 전용 모티프를 손으로 그린다. 연두·하늘색 같은 원색 로고도 넥타이에선 장난감처럼 튄다 — 같은
  모양을 은색·아이보리·연한 금으로 톤 다운한 새 subject를 만든다(기존 모티프는 두고, 2026-10-17 `ringtrio`).
- **개선하다 이웃 템플릿과 같아지지 말 것**: 핀 스트라이프를 `diagonal_pair` 엇갈림으로 바꿨더니 블록
  스트라이프(같은 배치·같은 파랑)와 똑같아져 사용자가 되돌렸다 — 밀도 규칙보다 목록 안 구별이 우선.
  배치를 바꾸기 전에 같은 카테고리 템플릿의 배치·바탕색을 대조한다(2026-10-17, 바둑판 복원 + 슬레이트).
- **사용자가 짚은 것만 고친다**: 윈도페인에서 "작은 십자" 하나를 짚었는데 가로·세로 줄·딥 브라운까지
  바꿨다가 "그 전이 더 좋아"로 되돌렸다 — 구조·색 변경은 사용자가 원할 때만(2026-10-17).
- **색 바꾸기는 효과가 작다**: 가로 바의 블루→틸에 "색상은 크게 의미 없는데"라는 반응 — 사용자는 로고
  크기·위치 같은 구성을 본다. 색은 사용자가 짚을 때만 바꾼다(2026-10-17).
- **기본은 엇박자(사용자 원칙, 2026-10-17)**: 명확한 지시가 없으면 작은 로고가 세로·가로로 일직선에
  서지 않게 한다. 일정한 배치는 그 디자인의 특징일 때만, 체크(칸 속 문장)는 예외. 엇박이 규칙적일
  필요는 없다. **하프드롭(`diagonal_pair`·`half_*`)도 두 행마다 같은 열로 돌아와 일직선이 보인다** —
  사용자가 세리프 R·가로 바·핀 스트라이프에 빨간 세로선을 그어 짚었다.
  **스트라이프 틈에 묶인 로고는 줄과 같은 우상향 띠로** — 가파른 `\` 사슬(비틀거린 것도, 곧은 것도)은
  "스트라이프는 우상인데 로고는 좌상"으로 기각됐다(2026-10-17). 틈 하나에 로고를 촘촘히(띠 안 간격이
  다른 이웃보다 짧게), 틈 한 줄 걸러 깔면 우상향 띠가 된다 — 한 레이어 `scatter` sateen으로(핀
  스트라이프: 타일 2배, k=4, order 16·step 7). sateen 점 x+y가 틈 간격의 배수인 (order, step)만 쓴다.
  줄 없는 올오버 로고도 우상향 사슬로 — **사슬도 결과 같은 45°**: `diagonal_2_3_up`(34°) 사슬은 "기울기가
  안 맞는다"로 기각됐다(2026-10-17). sateen 12·5(가장 가까운 이웃 (2,-2)/12, 다음 이웃 1.5배)로 로고를 두고,
  사슬이 x+y ≡ 0·½ 두 레인에 놓이므로 점은 레인마다 `diagonal_up` 경로(원점 + 바탕색 레인 밴드 0.499)로
  로고 사이 중점에 둔다(로고 하프드롭과 점, 타일 2배). **다음 이웃이 1.05배인 sateen(18·5 등)은 카드에서
  엉뚱한 27° 줄로 읽힌다** — 사슬 방향 이웃이 1.4배 이상 짧은 조합만. sateen step은 order와 서로소여야 한다
  (10·4 거부). 경로 위상은 렌더 SVG의 `<use translate>`를 파싱해 로고 중점과의 거리 0을 확인하며 맞춘다.
  점 격자 자리를 로고가 차지하는 도트형(세리프 R)은 로고 줄 띠로 바꾸지 말 것 — "R과 마름모가 엇박자로
  섞인 게 매력"으로 기각(2026-10-17). 흩어진 R + 나머지 전부 점은 avoid 이전엔 레이어 5개로 못 만들어
  원본(48mm 반복, R 세로 열)을 남겼고, `avoid_motif_layer`로 레이어 3개에 해결해 원본을 이 구성으로
  교체했다(2026-10-17 — 별도 템플릿으로 두니 원본과 차이가 거의 없어 하나만 둔다). sateen 8·3은 세로·가로 일직선은 없지만 완만한 사선 흐름은 보인다.
  흩어진 무늬 로고가 끝 엠블럼(큰 로고) 밑에 걸리면 panel에 바탕색(`"ground"` 슬롯 — 바탕색 변경을
  따라간다) 원 받침 `_disc(PANEL_LOGO, …)`만 깐다. 엠블럼은 panel 위에 그려지고, panel 로고로 바꾸지
  않으니 사용자 로고는 무늬 속 R 자리에도 그대로 들어간다. 반경이 크면 이웃 점이 반쯤 잘린다 —
  카드에서 보며 맞출 것(세리프 R: 반경 85, 중심 10 아래).
  가로 바 칸의 로고는 행마다 레인 경로 위상을 12mm씩 밀어 우상향 사슬로(타일 1.5배, 칸 3줄 = 바 + 레인
  + 경로 3 = 5레이어, 행당 2개). 2:3 사선 경로 하나로도 칸에 맞출 수 있지만 위상이 사슬 방향으로만 움직여
  끝 로고 밑에 작은 로고가 깔린 채 못 뺀다 — 끝 로고가 있으면 행별 경로로 위상을 따로 잡는다.
- **카드는 타일 크기에 따라 무늬 원점이 달라진다** — 같은 offset이라도 타일 72·120mm는 48·96mm와 바 위치가
  주기 절반(12mm) 어긋났다(2026-10-17, 끝 로고가 바에 걸림). 타일 배율을 바꾸면 끝 로고 칸 맞춤을 다시 본다.
- **엇박의 구조적 한계**: 무늬는 타일(카드 폭 ≈ 2.35타일) 단위로 반복돼 모든 자리가 1타일마다 같은
  열·행에 돌아온다. 타일당 로고 2~4개로는 어떻게 놓아도 열이 보이거나(정배치) 사선 줄이 된다 — 핀
  스트라이프에서 레인 경로 위상을 탐색해 봤지만 가장 고르게 퍼진 해가 `\` 대각 일직선이었다.
  스트라이프 틈에 묶인 로고는 더 그렇다(타일당 틈 2줄). 진짜 엇박은 타일을 키워(반복 주기를 늘려)
  타일당 자리를 늘려야 한다 — 플랜에 tile 크기가 없어 엔진/시드 쪽 기능이 필요하다(미구현).
- **작은 로고 반복을 빼는 처방은 템플릿마다 묻는다**: 세로 V·렙에선 받아들였지만 윈도페인에선 "로고
  한군데는 하지 말자"로 거절했다 — 칸 속 작은 문장이 그 템플릿의 맛일 때가 있다(2026-10-17).
- **포인트 로고**: 가운데 하단·큰 크기는 틀렸다 → 블레이드 오른쪽, 끝이 좁아지기 직전, 블레이드 폭의
  ~15%. 그리고 **한 점·한 폭으로 일괄 통일하지 말 것** — 로고 비율·크기에 따라 자리가 달라야 한다
  (면적 기준 + 오른쪽 아래 모서리 고정으로 해결, 2026-10-16).
- **로고 자리 순서 함정**: 장식 레이어가 먼저면 끝 로고에 장식이 뜬다(위 "로고" 절).
- 서브에이전트 10개 병렬은 잘 됐다 — 레포를 안 건드리게 하고 코드 조각만 받는 게 핵심.
- **방향**: 다양성을 내려고 사선을 좌상향(\\)으로 뒤집었다가 틀렸다 — 사선은 항상 우상향,
  다양성은 구조(굵기·묶음·행·가로 바)로 낸다(2026-10-16).
