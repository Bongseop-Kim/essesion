# E2E 01 스토어 잔여 분기 재실행 결과 — 2026-08-11

## 요약

- 환경: 로컬 store `:3000`(`VITE_E2E_MOCK_TOSS=true`), admin `:3001`, API
  `:8000`, PostgreSQL, fake GCS; Aside 브라우저.
- 생성 데이터: 상품 주문 `ORD-20260811-010`, 교환 클레임 `CLM-20260811-004`.
- 외부 대체 호출: mock Toss 승인 1건(42,000원), DRYRUN 전화 인증 SMS 1건,
  클레임 거부 DRYRUN Solapi 알림톡 1건. 실 Toss 0회, Recraft 0회.
- 브라우저 오류: store/admin 모두 console error 0건, pageerror 0건.
- 결과: 5개 흐름 PASS, 시드 상품 옵션 묶음 이름 누락 1건 FAIL.

## 실행 결과

| 흐름 | 판정 | 확인 내용 |
|---|---|---|
| 미인증 알림 결합 | PASS | 고객의 인증·알림 플래그만 테스트 시작 상태로 되돌린 뒤, 미인증 상태에서 서비스 알림 ON을 눌러 전화 인증 모달이 열리는지 확인했다. DRYRUN 인증 완료 뒤 서비스 알림이 자동 ON이 됐고 admin 고객 상세도 `전화 인증 완료`·`알림 동의`로 일치했다. |
| 주문·클레임 알림 | PASS | 새 상품 주문을 mock Toss로 결제하고 교환 클레임을 거부했다. `claim_notification_logs`는 `sent`, attempts 1이며 API 로그에 DRYRUN 알림톡 1건이 남았다. 상품 주문 상태 전이 자체에는 Solapi 발송 계약이 없고, `docs/api-spec/domains.md` 기준 클레임 완료·거부와 견적 접수만 알림 대상임을 함께 확인했다. |
| 활성 클레임 차단 | PASS | 교환 클레임 접수 중 admin 주문의 배송완료 버튼과 송장 수정이 disabled였다. 배송완료 버튼의 native tooltip `title`은 `활성 클레임이 있어 주문 상태를 변경할 수 없습니다`였고, 클레임 거부 뒤 액션이 복구됐다. |
| 상품 카탈로그 분기 | PASS | 홈 인기 상품 4개, `/shop` 초기 12개와 더 보기 후 14개, `3F-SEED-002`의 주문 전 `3개 남음`을 확인했다. 이 주문 1건이 재고를 소비해 최종 재고는 2개다. |
| 품절·복구 | FAIL | admin `/products/1`에서 롱 옵션 재고만 10→0으로 저장하려 했으나 시드의 `option_label`이 null이라 `옵션 묶음 이름을 입력해 주세요`로 차단됐다. UI에서 `길이`를 보완한 뒤에는 저장됐고 store `품절` 표시와 0→10 복구가 정상 동작했다. fresh seed와 아직 수정하지 않은 `3F-SEED-002`는 같은 누락을 유지한다. |
| 후기 게이트 | PASS | `ORD-20260811-010` 배송완료 상태에는 구매확정·반품·교환만 있고 후기 작성은 없었다. 구매확정 뒤 주문은 완료가 되고 반품·교환·구매확정이 사라지며 `후기 작성`이 나타났다. |

## 최종 상태

- 고객: 전화 인증 완료, 서비스 알림 동의·활성.
- 주문 `ORD-20260811-010`: 완료, 42,000원.
- 클레임 `CLM-20260811-004`: 교환 거부, 알림 outbox sent.
- `3F-SEED-001`: 옵션 묶음 이름 `길이`, 롱 옵션 재고 10개로 복구.
- `3F-SEED-002`: 이번 주문으로 일반 옵션 재고 2개, 옵션 묶음 이름은 여전히 null.
