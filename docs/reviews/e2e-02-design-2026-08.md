## 발견 목록

### FAIL

1. **디자인 예시 변경이 열린 store에 즉시 반영되지 않음**
   - 재현: admin에서 예시 순서 변경·게시 해제 → 이미 열린 store의 새 디자인 화면 확인.
   - 기대: 갤러리가 즉시 5건과 변경 순서로 갱신.
   - 실제: 기존 6건·순서가 유지되고 전체 reload 뒤에만 갱신.
   - 영향: 운영자의 큐레이션 변경이 최대 쿼리 캐시 수명 동안 고객에게 낡게 보인다.

2. **디자인 수정 단가 window-focus refetch 회귀**
   - 재현: admin에서 `design_edit_cost 2→3` → admin 탭을 거쳐 store 탭으로 복귀 → 토큰 상세 확인.
   - 기대: focus 시 `고치기 1회 3토큰`으로 갱신.
   - 실제: 2토큰이 유지되고 reload 뒤 3토큰으로 변경. 서버 차감은 3으로 정확했다.
   - 영향: 고객에게 표시되는 비용과 실제 차감 비용이 일시적으로 불일치한다.

### WARN

1. **scatter/lattice 프롬프트의 모티프 의미 보존 부족**
   - 배치 family는 맞았지만 동백꽃·페이즐리가 식별 가능한 모티프로 나오지 않았다. 8/4 후속에서 평가 플랜으로 이관한 항목이 런타임에서는 여전히 재현된다.

2. **범위 밖 수정의 안내 스낵바 미관측**
   - 모티프 패널 자동 확장, 저작 거절, 토큰 자동 환불은 정상이다. 세 번 반복해도 스낵바는 캡처되지 않았으며 admin에는 거절 3건이 남았다.

3. **사용자 취소 토큰 환불이 `거부`로 표시**
   - 신청 취소 자체와 재신청은 정상이나 store/admin 목록 모두 사용자 취소 건을 거부 상태로 표현한다. 기능 차단은 없지만 이력 의미가 혼동된다.
