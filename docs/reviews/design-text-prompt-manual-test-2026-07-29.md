## 확인된 원인

- 후보 선택 상태가 `candidateId`만 비교했다. 서로 다른 실행에서 같은 ID가 재사용되면 새 후보를 이미 선택한 것으로 오인해 선택 API를 호출하지 않았다.
- 화면의 후보 수가 성공 후 4로 초기화됐지만 실제 요청과 중복 제거 결과가 섞여, 설정값과 결과 안내가 일관되지 않게 보였다.
- refine 보존 가드는 요청하지 않은 범주는 복원했지만, 색상·간격처럼 명시한 범주가 실제로 변경됐는지는 검사하지 않았다.
- 과거 후보 선택 금지는 프론트와 API 양쪽의 의도된 선형 대화 정책이었다. 과거 후보를 활용할 별도 분기 흐름은 없었다.
- 자동 간격 보정 등 사용자가 조치할 수 없는 워커 경고까지 일반 Callout으로 노출돼 실제 해결 방법을 전달하지 못했다.

## 후속 결정

- 선택 상태를 `(runId, candidateId)`로 식별한다.
- 과거 후보는 현재 대화를 되감지 않고 새 대화로 분기한다.
- 후보 수는 대화별 마지막 제출값을 유지하고 새 대화만 4개로 시작한다.
- 사용자에게는 부분 생성과 인쇄 색역처럼 조치 가능한 안내만 최대 한 건 노출한다.
- 명시한 색상·모티프·기하·스트라이프 변경이 없으면 저작을 재시도한다.
- 스트라이프의 정확한 두께와 밴드 수를 수치적으로 강제하는 개선은 별도 후속 과제로 둔다.

수정 사항 검증은 `docs/plans/design-text-prompt-manual-test.md`의 A1–A5를 처음부터 다시 실행해 기록한다.

## C11 실행 결과 (같은 날 추가 실행)

새 세션·후보 1개·PC 1440×900에서 벌 생성→선택, 별 교체 생성→미선택, 스트라이프 발화 순서로 실행했다.

- 계약 판정 `PASS`: 스트라이프 결과의 모티프 심볼이 선택했던 벌(`motif-recraft-8907676a8f1d`)과 동일했고 미선택 별(`motif-recraft-01563a4ff05d`)이 아니었다. 선택된 정본만 수정 기준이라는 계약이 지켜졌다.
- UX 관찰: 발화 직전 입력창 바로 위에는 미선택 별 결과가 보였고, 실제 기준(벌)의 표시는 피드 위쪽의 체크 타일과 좌측 미리보기뿐이었다. 최신 결과만 보고 발화하면 별 기반으로 오인하기 쉬운 화면 구성이다.
- 추가 발견: 별 생성이 완료되는 순간 선택돼 있던 벌 타일이 과거 런이 되어, 체크 표시를 유지한 채로 라벨이 "새 대화로 이어가기"로 바뀌었다. 즉 현재 정본으로 표시된 타일을 다시 누르면 재선택이 아니라 세션 분기가 일어난다.
- 부수 확인: 첫 벌 생성이 `intent_invalid`(intent 저작 단계 거부)로 1회 실패했으나 토큰이 자동 환불됐고 같은 프롬프트 재시도로 성공했다. 토큰 회계는 500→495→490→485로 정확했다. 콘솔 오류 없음.

### 후속 개선 반영 (같은 날, 최종안으로 대체)

1차 개선(입력창 위 수정 기준 칩 + 분기 안내 캡션)을 적용했다가, "칩이 공간을 과하게 차지하고 과거 타일 클릭이 여전히 즉시 분기한다"는 피드백으로 같은 날 아래 최종안으로 대체했다. 서버 계약(select=최신 런만, 과거 후보는 branch)은 변경 없음.

- **클릭=조회 전용**: 과거 런 타일 클릭이 즉시 세션 분기하던 동작을 제거. 클릭은 좌측 패널에 조회 스테이징만 하고(제목 "이전 결과 미리보기"), 포인터 이동은 명시적 "이 이미지로 편집" 버튼으로만 실행한다. 모바일 과거 타일은 앵커 메뉴(미리보기·이 이미지로 편집)로 동일 규칙. 최신 런 타일 클릭=선택(포인터 이동)은 유지 — select는 무료·가역이다.
- **체크 → [편집중] 배지**: 선택 타일의 체크 원형을 `Badge`(brand solid) "편집중"으로 교체(`candidate-grid.tsx`). 입력창 근처 별도 표시가 없어졌으므로 모바일에서도 노출한다. 입력창 위 수정 기준 칩(`edit-basis-chip.tsx`)은 제거.
- 과거 런 캡션 문구를 조회 의미로 교체: "이전 결과예요. 후보를 누르면 미리보기로 확인할 수 있어요." 접근성 라벨도 "이전 결과 보기"로 변경.
- 재검증(Aside, PC): 과거(포인터) 타일 클릭 시 분기 없음 → 최신 후보 선택 시 배지 이동 → 과거 타일 클릭 시 패널 전환 + "이 이미지로 편집"/"미리보기 닫기" 노출 → 닫기 복귀 → 명시적 편집 클릭 시에만 새 세션 분기(스낵바 확인). 콘솔 오류 없음. `pnpm --filter store test`(237개)·`typecheck`·`pnpm lint` 통과.

### 포인터 규칙 변경: 생성 완료 시 첫 후보 자동 커밋 (같은 날)

"선택된 정본만 수정 기준"이던 계약을 "포인터는 항상 최신 결과물로 복귀(다수 후보는 첫 번째 자동 커밋)"로 변경했다. C11이 검증하던 기존 계약은 폐기되고 기대값이 반전됐다(`docs/plans/design-text-prompt-manual-test.md` 판정 원칙·C10·C11 갱신).

- 서버: `_finish_generation_success`에서 생성 턴 기록 직후 같은 트랜잭션으로 첫 후보를 select와 동일 경로로 커밋(`current_intent`·seed·colorway 갱신 + select 턴 기록). 워커 로그가 없으면 경고 후 스킵하고 생성 성공은 그대로 반환. 부수 효과: select 턴이 없어 대화 히스토리에서 통째로 빠지던 미선택 런이 이제 컨텍스트에 포함된다.
- 클라이언트: 생성 성공 시 낙관적 선택 오버라이드를 전 경로(prompt·variation·retry)에서 해제해 서버 자동 커밋이 배지·미리보기에 반영되게 함. 명시 선택은 최신 런 안에서 여전히 가능하고, 다음 생성이 완료되면 자동으로 최신 첫 후보로 대체된다(명시 지정 1회 유지 후 복귀).
- 검증: API 테스트 갱신·추가(`test_generation_auto_selects_first_candidate_as_conversation_context`, `test_generation_without_run_log_skips_auto_select`) 포함 `uv run pytest` 1151개·ruff·pyright 통과, store 테스트 237개·typecheck·lint 통과. 브라우저에서 발화 완료 즉시 수동 선택 없이 새 런 첫 후보로 `[편집중]` 배지가 이동하는 것을 확인했다. OpenAPI 스키마 변화 없음(codegen 불필요).

### "이 이미지로 편집" = 같은 대화의 정본 커밋으로 변경, 분기 UI 제거 (같은 날)

"이 이미지로 편집이 새 세션을 만드는 건 잘못 — 텍스트 입력의 기준으로 넘기는 용도이고, 새 대화는 새로 만들기(+)가 유일한 창구"라는 피드백 반영.

- 서버: select의 "최신 런만 허용"(409 `stale_design_selection`) 제약을 "이 세션의 성공 런이면 허용"으로 완화. 다른 세션의 런은 409 `design_result_unavailable`. 과거 후보 선택은 이력을 되감지 않고 `current_intent`만 교체하며, 다음 생성 완료 시 자동 커밋이 포인터를 최신으로 되돌린다(명시 지정 1회 유지 규칙이 추가 상태 없이 성립).
- 클라이언트: "이 이미지로 편집"이 branch 대신 기존 select 플로우를 호출. `useDesignBranch`와 분기 UI 경로를 전부 제거(새 대화는 "새로 만들기"만). 버튼 위계도 기본 액션과 동일한 레벨(neutralWeak)로 통일 — brandSolid 단독 강조가 어색하다는 피드백 반영.
- 서버의 branch 엔드포인트 자체는 남아 있다(웹 UI 미사용). 모바일 계획에도 없다면 제거 후 codegen 재생성이 후속 과제.
- 검증: `test_select_accepts_past_run_within_session_only` 추가 포함 design API 테스트 72개·ruff·pyright 통과, store 테스트 237개·typecheck·lint 통과. 브라우저에서 과거 후보 조회→"이 이미지로 편집" 시 같은 대화에 남은 채 배지만 해당 후보로 이동하는 것을 확인했다(콘솔 오류 없음). 플랜 문서 판정 원칙·C10을 새 계약으로 갱신.

### 클릭=조회 전면 통일·패널 액션 상시화 (같은 날)

추가 피드백 3건 반영. 서버 변경 없음(클라이언트만).

- 최신 런 타일 클릭이 즉시 select(포인터 이동)하던 예외를 제거 — **모든 타일 클릭은 신구 구분 없이 조회 스테이징만** 하고, 커밋은 "이 이미지로 편집"으로 통일했다. `TurnFeed`의 최신/과거 런 구분(`latestSelectableRunId`)·과거 런 캡션·라벨 분기·이중 메뉴가 전부 삭제됐고, 모바일 메뉴는 [미리보기·이 이미지로 편집·내려받기·다시만들기·실사화하기] 하나로 합쳐졌다.
- 다시만들기·내려받기·실사화하기는 **상시 노출**로 변경. "이 이미지로 편집"은 미리보기가 편집 대상이 아닐 때만 같은 줄 맨 앞에 나타난다. "미리보기 닫기" 버튼은 제거 — 편집 대상 타일을 다시 누르면 조회가 해제된다.
- 패널 버튼 4종의 배경을 전부 neutralOutline으로 통일 — weak 회색 채움(이 이미지로 편집·다시만들기)이 outline 버튼 옆에서 비활성처럼 오독된다는 피드백 반영.
- 편집 대상 전환 시 3버튼 깜빡임 수정: 낙관적 선택이 intent를 null로 두는 짧은 구간에 `selected`가 false로 떨어져 버튼이 disabled로 점멸하던 것을, 후보가 잡혀 있으면 켜진 상태를 유지하도록 변경(`selected: intent || candidate`). 액션 줄 교체(마운트/언마운트)도 사라져 점멸 요인 자체가 제거됐다.
- 검증: store 테스트 237개·typecheck·lint 통과. 브라우저에서 최신 후보 클릭→포인터 불변·"후보 미리보기" 전환·4버튼 공존, 커밋 시 배지 이동·편집 버튼만 소멸, 편집 대상 재탭 시 조회 해제를 확인(콘솔 오류 없음).

참고: 세션 첫 생성이 `intent_invalid`로 실패한 뒤 재시도에서 성공하는 패턴이 서로 다른 계정·세션에서 2회 재현됐다. 저작 안정성 이슈로 별도 확인 필요.
