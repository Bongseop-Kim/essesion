# `/design` 텍스트 프롬프트 수동 테스트

상태: 수정 후 재검증 미실행

대상: `http://localhost:3000/design`

범위: 텍스트 프롬프트, 후보 선택, 선택한 디자인의 대화형 수정

제외: 사진 첨부, SVG·텍스트·사진 모티프, 내 모티프, 색상 설정, 패턴 설정, 아이디어, 내려받기, 실사화

이 문서는 실행 전 테스트 지시서다. 실행을 마치면 결과를 `docs/reviews/`에 기록하고 이 파일은 `docs/plans/`에서 제거한다.

## 1. 먼저 알아둘 판정 원칙

- 같은 프롬프트가 매번 같은 그림을 만드는 계약은 아니다. 자연어 저작은 탐색적이며, 선택된 `intent + seed + colorway + engine/motif fingerprint`부터 결정론적이다.
- 최초 프롬프트는 구조적으로 다른 디자인 계획 2~4개를 저작한다. 화면의 후보 수는 1~4개로 선택할 수 있고 기본값은 4개다.
- 한 번의 최초 생성에서 나온 모든 후보는 같은 모티프 주제 집합을 사용해야 한다. 후보마다 벌·꽃·별처럼 주제가 제각각이면 실패다.
- 후보가 중복 제거되면 요청 수보다 적게 나올 수 있다. 이때 실제 후보 수와 조건을 단순화하거나 후보 수를 줄이라는 해결 방향이 함께 나오면 조건부 통과다.
- 성공한 생성은 **첫 후보를 자동으로 정본에 커밋**한다(포인터는 항상 최신 결과물로 복귀). 다른 후보를 기준으로 삼으려면 그 후보를 눌러 미리보기한 뒤 “이 이미지로 편집”으로 커밋한다 — 그 명시 커밋은 다음 생성이 완료되는 순간 다시 최신 첫 후보로 대체된다.
- 프롬프트에 “후보 1번”처럼 번호를 쓰지 않는다. 화면에서 `[편집중]` 배지가 붙은 `(실행, 후보)`가 다음 수정의 유일한 정본이다.
- 후보 타일 클릭은 실행의 신구를 가리지 않고 **조회(미리보기)만** 한다 — 클릭만으로 정본이 바뀌면 `FAIL`이다. 다음 발화의 기준으로 삼으려면 미리보기의 “이 이미지로 편집”(모바일은 타일 메뉴)으로 커밋한다 — 대화 이력은 되감지 않고 포인터만 옮긴다. 새 대화의 유일한 창구는 “새로 만들기”다.
- 후속 수정의 보존 여부를 비교할 때는 후보를 1개로 설정한다. 후보가 여러 개면 엔진의 정상적인 레이아웃 변형과 프롬프트 수정 효과가 섞인다. 후보 1개도 픽셀 동일성을 보장하지는 않으므로 작은 크기·셀 간격 변형은 `WARN`, 모티프 정체성·레이어 유무·배치 계열 변경은 `FAIL`로 본다.
- 후속 수정은 바꿀 항목과 유지할 항목을 짧은 문장으로 분리한다. “색상은 유지해. 모티프는 유지해.”처럼 카테고리를 직접 지정해야 보존 의도와 테스트 판정이 모호해지지 않는다.
- 텍스트만 사용한 자동 팔레트는 색 이름의 계열과 대비로 판정한다. 정확한 HEX 일치는 “색상” 설정 기능을 테스트할 때 다룬다.
- 현재 로컬 시드 기준 생성 1회는 5토큰, 신규 계정 기본 지급은 30토큰이다. 성공한 생성은 5토큰 차감되고, 워커 실패는 차감 행을 보상해 환불되어야 한다.

## 2. 실행 전 준비

2026-07-29 확인한 로컬 상태:

- store `/design`: 200
- api `/healthz`: 200
- worker `/healthz`: 200
- 공개 시드 모티프: 97개, Vertex embedding 97/97
- 활성 저작 예시: 25개, embedding 25/25
- 생성 비용: 5토큰
- 신규 계정 기본 지급: 30토큰

실행자는 다음을 확인한다.

- [ ] 고객 계정으로 로그인한다.
- [ ] 첫 방문 온보딩이 나오면 2페이지를 확인하고 “디자인 시작하기”를 누른다.
- [ ] “옵션 더보기”에서 사진·모티프가 선택되지 않았고 색상·패턴 설정 칩도 없는지 확인한다.
- [ ] “새로 만들기”를 눌러 이전 선택 문맥이 없는 새 세션에서 시작한다.
- [ ] 시작 잔액을 `B`로 기록한다. 계정을 이미 사용했다면 30토큰이라고 가정하지 않는다.
- [ ] 데스크톱에서는 좌측 “타일 / 넥타이” 미리보기와 우측 대화 영역이 모두 보이는 창 크기로 테스트한다.

## 3. 매 생성에서 공통으로 확인할 것

생성 중:

- [ ] 전송 후 입력과 옵션이 잠기고 중복 전송되지 않는다.
- [ ] “디자인을 생성하고 있어요. 수십 초 정도 걸릴 수 있어요.”와 후보 스켈레톤이 보인다.

성공 후:

- [ ] 입력한 프롬프트가 사용자 말풍선에 잘리지 않고 기록된다.
- [ ] 후보가 1개 이상 표시되고 깨진 이미지가 없다.
- [ ] 요청 수보다 후보가 적으면 이유를 알리는 안내가 표시된다.
- [ ] 프롬프트 입력창은 비고 후보 수는 이 대화에서 마지막으로 제출한 값이 유지된다.
- [ ] 잔액이 직전보다 정확히 5토큰 감소한다.
- [ ] 후보를 누르면 선택 표시가 생기고 좌측 미리보기가 갱신된다.
- [ ] 선택 후 “다시만들기 / 내려받기 / 실사화하기”가 활성화된다.
- [ ] “타일”에서 반복 경계가 끊기거나 흰 선이 생기지 않고, “넥타이”에서도 비율과 밀도가 자연스럽다.

실패 후:

- [ ] 오류 안내가 사용자 행동이나 재시도 방법을 설명한다.
- [ ] 프롬프트가 지워지지 않아 같은 내용으로 재시도할 수 있다.
- [ ] 새로고침까지 포함해 잔액이 원래 값으로 복구된다.
- [ ] 실패한 결과가 다음 선택 문맥으로 사용되지 않는다.

## 4. 기본 30토큰 핵심 시나리오

| ID | 세션 | 후보 수 | 비용 | 목적 |
|---|---|---:|---:|---|
| A1 | 새 세션 | 4 | 5 | 최초 생성, 시드 모티프 grounding, 후보 다양성 |
| A2 | A1 계속 | 1 | 5 | 색상만 변경, 구조 보존 |
| A3 | A2 계속 | 1 | 5 | 간격 변경, 색상·모티프 보존 |
| A4 | A3 계속 | 1 | 5 | 모티프만 교체 |
| A5 | A4 계속 | 1 | 5 | 기존 디자인에 스트라이프만 추가 |
| B1 | 새 세션 | 4 | 5 | 구체적 모티프가 없는 요청에서 모티프 비발명 |

모두 성공하면 예상 잔액은 `B - 30`이다. A1~A5는 각 단계 결과를 선택한 뒤 다음 프롬프트로 진행한다.

### A1. 벌 모티프 최초 생성

후보 수를 4개로 둔 뒤 입력한다.

```text
짙은 네이비 바탕에 작은 금색 벌 모티프를 대각선 방향의 반 칸 엇갈린 격자로 반복한 클래식 넥타이 패턴. 여백은 보통이고 스트라이프는 사용하지 마.
```

기대값:

- [ ] 성공 결과는 가능하면 4개다. 2~3개만 나오면 후보 부족 안내가 있어야 한다.
- [ ] 모든 후보에 벌 모티프가 있고, 꽃·나비·별 등 다른 주제로 바뀐 후보가 없다.
- [ ] 네이비 계열 바탕과 금색 계열 벌의 대비가 보인다.
- [ ] 벌은 작고 반복되며, 열이나 행이 반 칸 엇갈린 대각 흐름이 보인다.
- [ ] 명시적인 스트라이프 밴드가 없다.
- [ ] 후보끼리는 벌의 정체성은 같고 행·열 수, 간격, 기울기 같은 구조가 식별 가능하게 다르다.

실패 기준:

- 후보마다 서로 다른 모티프 주제가 나온다.
- 벌 대신 무관한 모티프만 나온다.
- 모든 후보가 사실상 색만 다르고 구조가 같다.
- 스트라이프 금지 요청을 모든 후보가 명백하게 위반한다.

가장 판단하기 쉬운 후보 하나를 선택한다.

### A2. 색상만 변경

“옵션 더보기 → 후보 1개”로 바꾼 뒤 입력한다.

```text
색상만 바꿔줘. 배경은 버건디, 벌은 아이보리로 해줘. 모티프는 유지해. 크기와 배치와 간격은 유지해.
```

기대값:

- [ ] 후보가 정확히 1개다.
- [ ] 배경은 버건디 계열, 벌은 아이보리 계열로 눈에 띄게 바뀐다.
- [ ] 벌 모티프와 반 칸 엇갈린 대각 격자 계열이 유지된다.
- [ ] 크기·위치·반복 간격은 직전 후보와 거의 같다. 작은 후보 변형은 `WARN`, 눈에 띄는 구조 변경은 `FAIL`이다.
- [ ] 새 스트라이프나 새 모티프가 생기지 않는다.

색만 바뀐 새 후보를 선택한다.

### A3. 간격만 더 여유롭게 변경

A2에서 제출한 후보 수 1개가 그대로 유지되는지 확인한 뒤 입력한다.

```text
간격을 더 넓혀 여유로운 반복으로 바꿔줘. 색상은 그대로 유지해. 모티프는 그대로 유지해.
```

기대값:

- [ ] 버건디·아이보리 계열과 벌 모티프가 유지된다.
- [ ] 같은 면적에 보이는 벌의 수가 줄거나 벌 사이 빈 공간이 확실히 넓어진다.
- [ ] 새 모티프나 스트라이프가 생기지 않는다.
- [ ] “타일” 반복에서 넓어진 간격도 경계 없이 이어진다.

새 후보를 선택한다.

### A4. 벌만 별로 교체

후보 수 1개가 그대로 유지되는지 확인한 뒤 입력한다.

```text
벌을 작은 별 모티프로 바꿔줘. 색상은 그대로 유지해. 크기와 배치와 간격은 그대로 유지해.
```

기대값:

- [ ] 벌이 사라지고 시드 카탈로그의 별 모티프가 나타난다.
- [ ] 별 이외의 제3 모티프가 추가되지 않는다.
- [ ] 버건디·아이보리 계열과 A3의 여유로운 반복 구조가 유지된다.
- [ ] 모티프 교체를 이유로 스트라이프가 새로 생기지 않는다.

새 후보를 선택한다.

### A5. 스트라이프만 추가

후보 수 1개가 그대로 유지되는지 확인한 뒤 입력한다.

```text
얇은 대각 스트라이프 두 줄만 추가해줘. 색상은 그대로 유지해. 별 모티프는 그대로 유지해. 모티프의 크기와 배치와 간격은 그대로 유지해.
```

기대값:

- [ ] 기존 별 반복 위에 얇은 대각 스트라이프 두 줄이 추가된다.
- [ ] 별 모티프와 기존 색 계열이 유지된다.
- [ ] 별의 크기·배치·간격은 직전 선택과 같다.
- [ ] 스트라이프가 모든 결과에 시각적으로 나타난다.
- [ ] “얇은 두 줄”의 정확한 두께·밴드 수는 관찰해 기록하되 이번 재검증의 차단 조건으로 삼지 않는다.

새 후보를 선택한다.

### B1. 모티프를 발명하지 않는 새 디자인

“옵션 더보기 → 새로 만들기”를 누른다. 후보 수는 4개로 둔 뒤 입력한다.

```text
차분하고 고급스러운 저녁 분위기의 미니멀 넥타이 패턴. 짙은 남색과 따뜻한 회색을 중심으로 하고, 구체적인 사물·동물·식물 모티프는 사용하지 마.
```

기대값:

- [ ] A 세션의 벌·별·스트라이프가 새 세션 문맥으로 새어 나오지 않는다.
- [ ] 구체적인 사물·동물·식물 아이콘을 임의로 만들지 않는다.
- [ ] 단색 면 또는 추상적인 스트라이프 구조 안에서 후보가 달라진다.
- [ ] 남색·따뜻한 회색 계열의 차분한 대비가 보인다.

실패 기준:

- 사용자에게 없는 꽃·동물·문장 같은 구체 모티프를 임의로 반복한다.
- A 세션의 별 모티프나 버건디 팔레트가 그대로 재등장한다.

## 5. 충전 후 선택 실행할 확장 시나리오

각 항목은 독립된 새 세션에서 실행한다. 비용이 드는 항목은 필요한 것만 선택한다.

### C1. 모티프 없는 스트라이프 전용

후보 수 1개:

```text
모티프 없이 네이비 바탕에 아이보리, 버건디, 골드 순서의 폭이 다른 세 줄 대각 스트라이프가 반복되는 클래식 리프 타이 패턴.
```

기대값: 구체 모티프 없이 세 개의 대각 밴드가 보이고, 밴드 폭과 색 순서가 구분된다.

### C2. 공개 카탈로그 모티프 2개

후보 수 4개:

```text
짙은 남색 바탕에 작은 꿀벌과 원 모티프를 번갈아 배치한 대각 물결 패턴. 두 모티프는 아이보리와 금색으로 구분하고 스트라이프는 넣지 마.
```

기대값:

- 모든 후보에 꿀벌과 원이 모두 등장한다.
- 후보마다 한쪽 모티프가 빠지거나 제3 모티프가 추가되지 않는다.
- 후보 간에는 같은 두 모티프를 사용하면서 경로·간격·위상이 달라진다.

### C3. 한영 혼합 프롬프트

후보 수 1개:

```text
Deep navy 바탕에 작은 white snowflake 모티프를 half-drop lattice로 반복한 차분한 winter tie pattern. 스트라이프는 제외해줘.
```

기대값: 언어가 섞여도 눈송이, 남색·흰색 계열, 하프드롭 격자, 스트라이프 제외가 유지된다.

### C4. 카탈로그에 없는 구체 모티프

후보 수 1개:

```text
짙은 남색 바탕에 작은 우주비행사 실루엣을 규칙적인 대각 격자로 반복한 넥타이 패턴. 흰색과 은회색만 사용해줘.
```

기대값:

- Recraft가 정상 구성된 환경이면 우주비행사 벡터 모티프가 생성된다.
- provider가 구성되지 않았거나 생성에 실패하면 명시적 오류와 토큰 환불로 끝난다.
- 어떤 경우에도 비행기·별·사람과 무관한 “가장 가까운 시드 모티프”로 조용히 대체하지 않는다.

### C5. 모티프 주제가 없는 짧은 요청

후보 수 4개:

```text
대담하고 현대적이며 에너지 넘치는 넥타이 패턴. 구체적인 모티프는 사용하지 마.
```

기대값: 모티프를 발명하지 않고 단색 또는 스트라이프 구조로 해석한다. 구체 모티프가 나오면 실패다.

### C6. 선택하지 않은 후보의 문맥 비전진

1. 새 세션에서 아무 프롬프트로 후보를 만든다.
2. 후보를 선택하지 않는다.
3. “방금 디자인의 색만 빨강으로 바꿔줘”를 입력한다.

기대값: 선택된 정본이 없으므로 직전 후보 중 하나를 임의로 수정하면 안 된다. 새 최초 요청으로 처리되거나, 더 명확한 입력이 필요하다는 오류로 끝나야 한다.

### C7. 다시만들기와 작성 중 프롬프트 분리

1. 선택된 디자인이 있는 상태에서 입력창에 아직 전송하지 않은 문장을 적는다.
2. 좌측 “다시만들기”를 누른다.

기대값:

- 다시만들기는 선택된 디자인의 seed variation만 만든다.
- 입력창의 미전송 문장은 variation 요청에 섞이지 않고 그대로 남는다.
- variation도 생성 1회 비용인 5토큰을 사용한다.

### C8. 4,000자 API 경계

- 공백이 아닌 4,000자 프롬프트는 API 계약상 허용된다.
- 4,001자는 생성 과금 전에 거부되어야 하며 잔액이 줄면 안 된다.
- 현재 화면 입력에는 별도 길이 카운터가 없으므로, 4,001자에서 일반 오류만 보이면 백엔드 경계는 통과하되 UX 개선 항목으로 기록한다.

### C9. 새로고침 복원

성공 후보를 선택한 뒤 페이지를 새로고침한다.

기대값:

- 같은 세션의 프롬프트와 생성 결과가 다시 보인다.
- 마지막으로 선택한 후보가 선택 상태와 좌측 미리보기로 복원된다.
- 새로고침 자체로 토큰이 차감되거나 generation이 재실행되지 않는다.
- 후보 수가 이 대화의 마지막 제출값으로 복원된다.

### C10. 과거 후보 조회와 정본 커밋

1. A1–A5가 남아 있는 대화에서 A1의 후보 하나를 누른다.
2. 좌측 미리보기가 "이전 결과 미리보기"로 바뀌고 정본(`[편집중]` 배지)은 그대로인지 확인한다.
3. 미리보기의 "이 이미지로 편집"을 누른다(모바일은 타일 메뉴에서 선택).
4. 같은 대화에 남아 있는지, `[편집중]` 배지가 A1 후보로 이동했는지 확인한다.
5. 다음 프롬프트를 입력해 결과가 A1 후보 기반인지, 완료 후 배지가 새 결과의 첫 후보로 복귀하는지 확인한다.

기대값:

- 1의 클릭만으로는 정본이 바뀌지 않는다. 클릭이나 3의 버튼으로 새 대화가 생성되면 `FAIL`이다 — 새 대화의 유일한 창구는 "새로 만들기"다.
- 3 이후 대화 이력은 그대로이고 `[편집중]` 배지·좌측 미리보기만 A1 후보로 이동한다.
- 5의 결과는 A1 후보 기반이어야 하고, 생성 완료와 함께 배지가 새 실행의 첫 후보로 자동 복귀해야 한다(명시 지정 1회 유지).
- 정본 커밋 자체로 토큰이 차감되거나 이미지 생성이 다시 실행되지 않는다.

### C11. 새 결과 미선택 상태의 연속 발화 기준 확인

새 결과를 별도 선택하지 않고 연속 발화하면 무엇이 수정 기준이 되는지 확인한다. 성공한 생성은 첫 후보를 자동 커밋하므로(판정 원칙 5항) 기준은 항상 최신 결과여야 한다. 새 세션에서 후보 수 1개로 실행하며 비용은 15토큰이다.

1. A1 프롬프트로 벌 디자인을 생성한다. 선택하지 않아도 후보에 `[편집중]` 배지가 붙는지 확인한다.
2. A4 프롬프트로 벌을 별로 교체한 결과를 만들되, 후보를 **선택하지 않는다**. `[편집중]` 배지와 좌측 미리보기가 2의 별 후보로 자동 이동했는지 확인한다.
3. A5의 스트라이프 프롬프트를 그대로 입력하고, 결과가 벌·별 중 무엇을 기반으로 했는지 기록한다.

기대값:

- 결과는 2의 별 디자인 기반이어야 한다(자동 커밋된 최신 정본). 벌 기반이 나오면 `FAIL`이다.
- 각 생성 완료 직후 `[편집중]` 배지가 새 실행의 첫 후보로 이동하지 않으면 `FAIL`이다.
