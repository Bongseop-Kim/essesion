# 계측 마무리 — 배포 후 검증과 UTM

**전제**: 콘솔 설정은 2026-08-19에 전부 끝났다(결과는
`docs/reviews/analytics-posthog-2026-08-19.md`). 코드도 끝났고 GitHub 변수도 주입됐다.

남은 것은 **배포가 있어야 가능한 검증**과 **광고를 시작할 때 하는 일** 둘뿐이다.
이 둘이 끝나면 이 문서를 지운다.

## 1. 배포 후 검증 — CSP가 핵심

**실행 조건**: 커밋·머지 후 CI 성공, 프론트 배포 완료. 그 전에는 실행할 수 없다.

`worker-src 'self' blob:`를 CSP에 새로 넣었다. 틀리면 `default-src 'none'` 폴백에 걸려 리플레이
워커가 죽는데, **CSP 위반은 콘솔에만 찍히고 SDK는 에러를 던지지 않는다.** "켰는데 녹화가 없다"로
나타나 몇 주 뒤에야 발견하게 된다. 로컬 dev·preview는 `public/_headers`를 읽지 않아 이 검증만은
배포 후에만 가능하다.

1. `https://essesion.shop` 열고 DevTools 콘솔에 **CSP 위반이 하나도 없는지** 확인.
2. Network에서 `us.i.posthog.com/flags/`·`/i/v0/e/`가 200인지 확인.
3. PostHog에서 **자기 세션 리플레이를 재생한다.** `/shop`·`/design`은 보이고
   `/order`·`/my-page`는 플레이스홀더로 가려져야 정상이다.
   **주소·연락처가 읽히면 즉시 리플레이를 끄고 해당 녹화를 삭제한 뒤 마스킹을 고친다.**
4. 상품 상세 → 장바구니 → 결제 시작을 태우고, PostHog 활동 탭에서 `view_item`·`add_to_cart`·
   `begin_checkout`이 GA4와 같은 이름으로 들어오는지 대조. **프로덕션에서 실제 주문을 만들지 않는다.**

1·2는 에이전트가 할 수 있다(브라우저 확인은 `.claude/skills/aside-browser/SKILL.md` 하네스).
3은 PostHog 로그인이 필요해 사람이 한다.

## 2. UTM 값 확정 — 첫 광고 직전에만

**실행 조건**: 광고 채널이 정해졌을 때. 계획은 2026년 10~11월경이고 채널은 미정이다.
**그 전에는 실행하지 않는다** — 지금 값을 정해봐야 그때 다시 정하게 된다.

형식 규칙(소문자, `utm_medium` 4종, `utm_campaign`은 연월-이름)은 `docs/analytics.md`에 있다.
채널이 정해지면 **그 문서의 `utm_source` 표를 먼저 채우고, 그 다음 링크를 만든다.** 링크부터
만들면 표기가 갈리고 사후에 못 고친다.

## 되돌리는 법

- **PostHog 끄기**: `gh variable delete VITE_POSTHOG_KEY` — 모듈이 no-op이 되어 코드 롤백 없이
  꺼진다. `deploy.yml` 게이트에 일부러 넣지 않았으므로 배포는 계속된다.
- **GA4 끄기**: `VITE_GA_MEASUREMENT_ID`는 frontend job 게이트라 **지우면 프론트 배포 자체가
  스킵된다.** 게이트 조건을 함께 손봐야 한다.
- **상향 신호**: 무료 한도(월 100만 이벤트 / 5,000 리플레이) 근접 시 샘플링을 더 낮춘다.
  `purchase` 건수가 DB 주문 건수보다 20% 이상 적으면 서버사이드 전송을 검토한다.
