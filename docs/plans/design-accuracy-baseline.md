# 디자인 정확도 평가의 변별력 보강

2026-09-09 [실모델 기준선](../reviews/design-accuracy-baseline-2026-09-09.md)에서 **닫지 못한 것만** 남겼다.
기준은 확정됐고(`design-accuracy-v3`, reviewed) 그 기준으로 **30/30이 2회 재현**된다.
그래서 남은 문제는 정확도가 아니라 **변별력**이다 — 지금 코퍼스로는 모델이 나빠져도 알아채지 못한다.

## 왜 필요한가

| 근거 | 사실 |
|---|---|
| [기준선 기록](../reviews/design-accuracy-baseline-2026-09-09.md) | 확정 기준(v3)에서 30/30이 2회 나왔다. **만점 코퍼스는 회귀를 잡지 못한다** — 모델·프롬프트가 나빠져도 통과율이 그대로일 수 있다. |
| 같은 기록의 RAG A/B | 예시 있음/없음이 첫 생성 8건에서 **같은 6/8**이었다. 예시가 기여할 만한 추상·분위기 요청이 코퍼스에 없다 — 코퍼스의 빈 곳이지 RAG의 결론이 아니다. |
| 같은 기록 | v3 두 실행에서 최종 intent가 같은 사례는 23/30이다. 조건이 걸지 않은 축(크기·밴드 폭)은 매 실행 달라진다 — 변별력을 붙일 여지가 그만큼 있다. |
| 같은 기록 | v2 실행에서 "흰 바탕" 요청에 짙은 청록이 나온 적이 있다(1회). 지명색은 실패 가능한 축인데 현재 사례가 얇다. |
| 같은 기록 | 모델의 이전 출력을 다음 턴에 연결하는 대화 평가는 아직 없다. 편집 18건은 전부 고정 fixture에서 시작한다. |
| [design-evaluation.md](../api-spec/design-evaluation.md) | 원·별 fixture는 카탈로그 의미 검색을 검증하지 않는다. "고양이를 넣어줘" 같은 grounding 정확도는 범위 밖이다. |

## 범위 밖

엔진·샘플러·RAG 구현 변경. 2026-09-09에 측정으로 닫았다(각각 근거는 위 기록 §함께 닫은 항목).
곡선 bbox 정밀화도 같은 이유로 하지 않는다 — 재론 조건은 아래 §재론 조건.

## 실행 조건

- 유료 호출은 `--confirm-live`와 명시적 동의가 있을 때만. 없으면 기다린다.
- 코퍼스 문장·조건 변경은 **사람이 확정한 뒤에만** 반영한다. 실패한 사례를 통과시키려고 조건을 고치지 않는다.
  기준값이 필요하면 엔진 안의 근거(예시 `size_ratio` 등)를 찾아 쓰고 그 출처를 적는다.
- 기준을 바꾸면 `revision`을 올리고 이전 기준선 수치와 나란히 기록한다 — 같은 revision의 수치만 비교한다.
- 사례를 늘린 뒤 통과율이 떨어져도 **모델이 나빠진 것이 아니다** — 그렇게 보고하지 않는다.

## 절차

1. **변별력 있는 사례를 추가한다.** (30/30이 나왔으므로 이것이 최우선이다)
   [design_accuracy_cases.json](../../apps/worker/scripts/design_accuracy_cases.json)에 더한다.
   근거: 지금 30건은 색·배치를 문장이 직접 지정해서 모델이 틀릴 여지가 거의 없다.
   - **지명색**을 여러 개 섞은 요청(바탕·줄·강조가 경쟁하는 문장)을 넣는다 — v2에서 실제로 틀린 축이다.
   - "차분한 봄 느낌", "격식 있는 회의용" 같은 **추상 요청**을 넣되, 조건은 intent·좌표로 판정 가능한 것만 건다
     (분위기 자체를 채점하지 않는다).
   - 두 모티프의 **관계**를 지정하는 요청(하나는 크게 하나는 작게, 하나만 줄 위에)을 넣는다.
   - 조건이 걸지 않아 매 실행 달라지는 축(크기·밴드 폭)에 상한/하한을 붙일 수 있는지 검토한다 — `lte`/`gte`가 있다.
   - 추가 후 `revision`을 올리고 예시 있음/없음 A/B를 다시 돌린다. 그때도 차이가 없으면 top-3 유지를 근거와 함께 기록한다.

2. **대화 기준선을 측정한다.**
   [collect_design_accuracy.py](../../apps/worker/scripts/collect_design_accuracy.py)를 확장한다.
   근거: 실제 사용자는 고정 fixture가 아니라 **모델이 직전에 만든 결과**를 이어서 고친다.
   - 첫 생성 결과를 다음 턴의 baseline으로 넘기는 2~3턴 체인을 만들고, 각 턴의 조건을 따로 채점한다.
   - `conversation_history`를 실제로 채워 넣는다(지금은 빈 목록이다).
   - 누적 실패(1턴 오답이 2턴을 망치는 경우)와 고정 baseline 결과를 나눠서 보고한다.

3. **카탈로그 grounding을 별도로 평가한다.**
   근거: 원·별 fixture는 검색을 타지 않아 "어떤 그림을 골랐는가"를 검증하지 못한다.
   - 실제 카탈로그를 쓰는 소수 사례로 subject 일치·근사 매칭 경고 발생 여부를 판정한다.
   - 모티프 생성(GPT Image)은 호출하지 않는다 — 검색·근사 매칭까지만 본다.

## 검증

- 오프라인: `uv run pytest apps/worker/tests/test_design_accuracy.py apps/worker/tests/test_scatter_streams.py`.
- 수집·채점: `collect_design_accuracy.py --confirm-live` → `eval_design_accuracy.py --outputs …`.
  겹침을 볼 때만 `--ink-overlap`(렌더러 필요). 결과에는 모델·프롬프트/컴파일러 revision·코드 SHA·반복 횟수·지연을 함께 싣는다.
- 기준 변경 전후 수치를 같은 표에 놓고, 무엇이 모델 변화이고 무엇이 기준 변화인지 구분해 적는다.

## 재론 조건

- **곡선 bbox 정밀화**: AI 생성(gpt_image) 모티프의 크기가 작아 보인다는 실제 불만이 나오면.
  측정값은 0.854·0.947(n=2)이고 카탈로그·업로드는 0.98 이상이다. 고치려면 기존 저장 모티프의
  identity 이관 계획을 먼저 세운다.
- **샘플러 교체**: 산개 개수 미달 경고가 실제 로그에 쌓이면. 2026-09-09 기준 60회 실행에서 0건이다.
- **산개 개수 미달 전용 고객 문구**: 위 경고가 쌓이고 고객에게 설명할 표현이 정해지면
  (api 스키마 변경 + `pnpm codegen` 동반).

**실패 모드:** 기준을 고쳐 통과율을 올려 놓고 모델이 좋아졌다고 쓰는 것, 8건짜리 A/B로
RAG가 무용하다고 결론 내리는 것, 그리고 만점 코퍼스를 품질 보증으로 착각하는 것이다.
