# 수선 발송 확인 페이지: 확인 박스 제거, 입력 폼 바로 노출, 모바일 하단 고정 버튼

2026-11-19 운영자 요청으로 작성했다. 스토어 `/order/:orderId/repair-shipping`(수선 주문 `발송대기` 상태에서 고객이
발송 사실을 알리는 페이지)에서 두 가지를 고친다. 선행 조건은 없다.

## 왜 필요한가

- 페이지에 들어가면 "수선품을 발송했습니다." 선택 박스(`SelectBox`) 하나만 보이고, 이걸 눌러야 택배사·송장번호·
  사진·메모 입력칸이 나온다(`apps/store/src/pages/order/repair-shipping.tsx:126-153`). 박스가 버튼처럼 보이지 않아
  운영자가 직접 써 보고 무슨 화면인지, 무엇을 해야 하는지 몰랐다.
- 이 박스는 주문서의 "이미 발송했어요" 체크박스(`apps/store/src/pages/order/order-form.tsx:351-366`)를 옮겨 온
  것이다. 주문서는 아직 안 보낸 고객이 있어 체크가 필요하지만, 이 페이지는 발송을 알리러 들어오는 곳이라 같은
  선언을 한 번 더 받는 셈이다.
- "발송 확인" 버튼은 본문 맨 아래에 있다(`repair-shipping.tsx:155-171`). 모바일에서는 스크롤해야 보인다.
- 송장·사진·메모는 지금도 전부 선택이고 빈 폼도 유효하다(`apps/store/src/features/repair-shipping/model/shipment.ts:70-89`).
  박스를 없애도 "송장 없이 보냈다고만 알리기"는 그대로 된다.

## 범위 밖

- 주문서의 "이미 발송했어요" 체크박스. 주문서에서는 필요하다.
- 안내 문구 추가. 입력칸 위 설명이나 부연 텍스트를 새로 넣지 않는다(운영자 지시). 기존
  `invalidReason`(버튼이 비활성인 이유) 표시만 유지한다.
- api·명세 변경. 제출 바디는 그대로다.

## 절차

1. `apps/store/src/shared/ui/content-layout.tsx:93-99` — 데스크톱에서 `sidebar` 없이 `actionBar`만 있으면
   본문(`children`) 아래에 `actionBar`를 그린다. 지금은 `:101-110` sidebar 안에서만 그려서, 이 항목 없이 3번을
   하면 데스크톱에서 버튼이 사라진다. 그래서 먼저 실행한다. 2026-11-19에 확인한 바로는 `actionBar`를 넘기는
   9곳이 모두 `sidebar`도 넘기므로 기존 화면은 바뀌지 않는다(실행 전 `grep -rn "actionBar=" apps/store/src`로
   다시 확인). prop 주석(`:25`)도 "sidebar 없으면 본문 아래"로 고친다.
2. `apps/store/src/pages/order/repair-shipping.tsx`
   - `:48-49` `confirmedShipment` 상태와 주석을 지운다.
   - `:126-144` `SelectBox` 블록을 지우고, `:146-153`의 조건을 풀어 `RepairShipmentFields`를 항상 렌더한다.
   - `:160` 버튼 `disabled`에서 `!confirmedShipment`를 뺀다.
   - 쓰지 않게 된 `SelectBox`·`SelectBoxItem` import를 지운다.
   - 버튼 라벨 "발송 확인"을 "발송 완료 알리기"로 바꾼다. 박스가 하던 "실수로 누르지 않게" 역할을 문구가 대신한다.
     페이지 제목·브레드크럼의 "발송 확인"은 그대로 둔다.
   - 잘못 눌렀을 때의 영향: 빈 폼이 유효하므로 한 번 누르면 주문이 `발송확인중`으로 넘어간다. 이 페이지는
     `발송대기`가 아니면 주문 상세로 돌려보내므로(`:73-75`) 고객이 스스로 되돌리거나 송장을 나중에 넣을 화면은
     없다. 다만 `발송확인중`에서도 취소 요청은 그대로 되고(`docs/api-spec/money.md` 고객 액션), 실물이 오지
     않으면 관리자가 확인한다. 돈이 움직이지 않는 전이라 확인 단계를 따로 두지 않는다. "발송 안 했는데
     발송확인중이 됐다"는 문의가 들어오면 확인 다이얼로그를 검토한다.
3. 같은 파일 `:155-171` 버튼과 `invalidReason` 블록을 본문에서 빼서 `ContentLayout`의 `actionBar` prop으로 넘긴다.
   로딩·에러 상태에서는 `actionBar`를 넘기지 않는다(주문이 로드됐을 때만). 근거: 모바일 하단 고정 바와 safe area
   처리가 이미 `ContentLayout`에 있다(`apps/store/src/shared/ui/content-layout.tsx:130-151`).

## 검증

- `pnpm lint && pnpm --filter store typecheck && pnpm --filter store test`
- 사용자가 띄워 둔 스토어(:3000)에서 `발송대기` 수선 주문의 발송 확인 페이지를 연다.
  - 들어가자마자 입력칸이 보이고 선택 박스가 없다.
  - 모바일 폭에서 "발송 완료 알리기"가 하단에 고정되고, 데스크톱에서는 입력칸 아래에 보인다.
  - 빈 폼 제출, 택배사만 고른 상태(버튼 비활성 + 이유 표시), 송장·사진 입력 후 제출이 각각 동작하고 주문 상세로 이동한다.
  - 주문서에서 "이미 발송했어요"로 넘어온 경우(prefill) 입력값이 채워져 있다.

## 기각한 대안

- **박스를 진짜 버튼 모양으로 바꾸기**: 한 번 더 눌러야 폼이 나오는 단계 자체가 불필요하다.
- **이 페이지에서만 `useBreakpoint`로 버튼 위치 분기**: 같은 분기가 이미 `ContentLayout`에 있다. 레이아웃에서
  한 번 처리하는 편이 다음 페이지에도 쓰인다.

실패 모드: 1번(`ContentLayout`)을 빠뜨리고 3번만 해서 데스크톱에서 제출 버튼이 사라지는 경우다.
