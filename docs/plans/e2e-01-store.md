# E2E 01 — 스토어 구매·마이페이지 (Aside) — 실행 지시서

스테이징 개통 전 로컬 점검 4부작의 1편. 상품 조회→장바구니→주문→클레임→구매확정→후기의
전 수명주기와 마이페이지 전반. 디자인은 `e2e-02`, 주문제작·샘플은 `e2e-03`, 수선은 `e2e-04`.

## 공통 전제 (4부작 동일)

- 서버 확인: store :3000 / api :8000 / worker :8001 / DB(`docker compose ps`).
- **mock Toss**: store가 `VITE_E2E_MOCK_TOSS=true`로 떠 있어야 한다 — 결제 페이지에 "테스트
  결제 수단" 문구. 실 Toss 위젯이 보이면 **누르지 말고 중단**. 백엔드는 시크릿 없음(DryRun).
- **Recraft 0회** 정책(전 플랜 공통). OpenAI LLM·임베딩은 자유.
- 시드 확인 3종(admin_settings·motifs·design_examples). 계정은 `customer@local`·
  `admin@local`(비밀번호는 `.claude/skills/aside-browser` 참조) — 기본 로그인은 사용자가
  미리 준비하되, 시나리오가 요구하는 실행 중 로그인(S5·Q3 등)은 에이전트가 직접 수행한다.
  데이터는 시드가 출발점 — 주문·클레임 등은 실행이 만든다.
- 탭마다 console·pageerror 리스너, 시나리오 종료 시 0건 확인. `snapshot(page)` 기본.
- 알림이 발생하는 단계(주문·클레임·인증)에서 api 로그의 `DRYRUN solapi` 기록 확인.
- 중단 규칙: 503 `missing_configuration`→재시드 후 계속, 스키마 오류→중단.
  개별 FAIL은 기록하고 다음 시나리오 계속.
- 결과 기록·후속은 아래 "결과 기록과 후속" 절을 따른다 — **4부작 공통 규칙**.

## 결과 기록과 후속 (4부작 공통)

실행이 끝나면 `docs/reviews/e2e-0N-<도메인>-2026-08.md`를 다음 구조로 작성한다
(이 플랜은 `e2e-01-store-2026-08.md`):

1. **머리말** — 실행일, 기준 커밋 해시(`git rev-parse HEAD`), 실행 환경 한 줄,
   그리고 **Recraft 0회·실 Toss 0회** 명시.
2. **판정표** — `| ID | 판정 | 확인 내용/증거 |`. 판정은 PASS/WARN/FAIL/SKIP.
   SKIP은 사유(정책·선행 조건 미충족·기소비 계정 등)를 반드시 병기.
3. **발견 목록** — FAIL·WARN 각각: 재현 경로, 기대 동작 vs 실제 동작, 콘솔·api 로그 증거,
   심각도(배포 차단/후속 수정/관찰). 8/4의 `design-flow-e2e-2026-08-04.md`가 형식 선례.

데이터 원복은 불필요 — 로컬 도커 DB라 실행이 남긴 데이터·설정 변경은 그대로 둔다.
단, **같은 실행의 뒤 시나리오가 의존하는 값은 복구**한다(각 행에 명시).

후속 처리:

- **FAIL은 그 자리에서 수정하지 않는다.** 결과 문서에 기록하고 실행을 계속한 뒤,
  수정은 사용자 확인을 받아 별도 후속 플랜(`docs/plans/e2e-0N-followup.md`)으로 진행한다
  — 8/4의 발견 7건 → `design-flow-e2e-followup-2026-08.md` 전례를 따른다.
- 결과 문서 작성 후 **이 플랜 문서를 `docs/plans/`에서 제거**한다(레포 규칙).
- `docs/CHECKLIST.md` §6의 E2E 항목에 해당 도메인의 로컬 검증 완료를 각주로 갱신한다
  (스테이징 몫 — 소셜 로그인·Cloud Tasks·실 Toss — 은 미완료로 유지).
- **4편이 모두 끝나면**: 배포 차단급 FAIL이 없을 때 스테이징 개통(체크리스트 §1,
  `infra/README.md` 부트스트랩)으로 넘어갈 준비가 된 것 — 사용자에게 그렇게 보고한다.

## 시나리오

S0~S5는 별도 시크릿 컨텍스트 탭에서 수행한다 — 비로그인으로 시작해 S5에서 그 탭 그대로
로그인해 병합을 확인한다.

| ID | 단계 | 확인 |
|---|---|---|
| S0 | 홈 | 히어로 배너 4종 링크(design/custom-order/shop/reform), 인기 상품 4개→상세. **홈 후기 섹션은 하드코딩 정적 데이터** — 렌더만 확인 |
| S1 | `/shop` 목록 | 필터 4종(카테고리·색상·패턴·소재)+정렬, 초기화 버튼(필터 없으면 disabled, 정렬은 유지), 0건 조합 → "조건에 맞는 상품이 없습니다", 12개 초과 시 더 보기/무한스크롤(현재 뷰포트 것만) |
| S2 | 상품 상세 | 옵션 선택(`(+₩N)` 추가금), 수량 스테퍼 상한=재고, **옵션 변경 시 수량 1로 리셋**, 재고 ≤5 옵션 "N개 남음" |
| S3 | 품절 분기 | admin에서 시드 상품 옵션 하나 재고 0으로 → 해당 옵션만 disabled·"품절"(다른 옵션은 구매 가능) → 전 옵션 0 → "품절" 뱃지+버튼 disabled → **재고 복구(이후 구매 시나리오가 이 상품을 쓴다)** |
| S4 | 게스트 장바구니 (비로그인) | 담기 가능(게스트 카트), 같은 (상품,옵션) 재담기 → "이미 장바구니에 있는 상품입니다" 다이얼로그, 재고 초과 담기 → "재고는 N개까지" 스낵바 |
| S5 | 게스트→로그인 병합 | S4 상태로 로그인 → "장바구니를 계정에 동기화했습니다" 스낵바, 항목 보존 |
| S6 | `/cart` | **수량 변경은 "옵션 변경" 모달에서만**(목록에 스테퍼 없음), 옵션 변경으로 기존 항목과 겹치면 병합·수량 합산, 전체선택(확인 필요 항목 제외·indeterminate), 선택 삭제 다이얼로그 |
| S7 | 쿠폰 | 시드 테스트 쿠폰 적용(라인 단위) → 원가 취소선+할인가+"쿠폰명 적용", 결제 후 재사용 불가 |
| S8 | 주문서 | 배송지 0건이면 등록 모달이 폼 모드 강제, 첫 배송지 자동 기본, 변경 모달 목록/폼 전환 |
| S9 | **결제(mock)** → success | "테스트 결제 수단" → 결제 → success → 주문 상세 금액·품목 일치, 장바구니에서 결제 항목 제거, **success 새로고침 → 멱등(중복 주문 없음)** |
| S10 | fail 페이지 | `/order/payment/fail`·`/token/purchase/fail` 직접 진입 시 안내 렌더 |
| S11 | customerActions 상태별 노출 | 결제 직후(진행중): 취소만 → admin에서 **배송중** 전환 → 반품·교환·구매확정 노출 → **배송완료**에서도 동일. 서버 계산값이므로 상태마다 새로고침 후 확인 |
| S12 | 클레임 수명주기 | 배송중 주문에 교환 신청(사유 세트가 타입별로 다름·수량 필드는 qty>1일 때만) → **활성 클레임 중 다른 클레임·구매확정 버튼 전부 숨김** → admin 거부 → 버튼 복귀 → 반품 신청 → admin 완료 처리 → store 상태 반영 |
| S13 | 클레임 신청 취소 | **S12의 admin 처리 전에** 수행: 반품 클레임이 `접수` 상태일 때 상세에 "신청 취소" 노출 → 취소 → 목록 복귀 + 주문 상세에서 재신청 → 재신청 건을 S12의 admin 완료 처리로 넘긴다 |
| S14 | 구매확정 | 별도 주문(클레임 없는)을 배송완료로 → 확인 다이얼로그 → 확정 → **클레임 액션 소멸** + 후기 버튼 노출 |
| S15 | 후기 | sale 주문은 **품목별** 후기 작성 → "작성한 후기 보기" 전환 → 상품 상세 후기 탭에 별점·본문 반영 (홈 후기 섹션은 정적이라 미반영이 정상) |
| S16 | 마이페이지 목록 | `/my-page` 메인(계정 상태 3행·메뉴), 주문 내역 유형 필터 6종, 클레임 필터 5종, 필터별 빈 상태 문구 분기 |
| S17 | 상품 문의 | 상품 상세에서 비밀글 문의 작성 → 타 계정(비로그인)에선 자물쇠 disabled → `/my-page/inquiry`에서 수정·삭제 다이얼로그 → admin 답변 → store 답변 블록 표시 |
| S18 | 내 정보·알림 | 이름·생년월일 저장, **휴대폰 인증: 인증번호는 api 로그의 `DRYRUN solapi` 출력에서 확인해 입력**, 60초 재전송 쿨다운. 알림 설정: 미인증 상태에서 서비스 알림 ON → 인증 모달 선행 → 인증 성공 시 자동 ON |
| S19 | 배송지 관리 | 등록·수정·삭제(다이얼로그)·기본 설정, **기본 배송지엔 삭제·기본설정 버튼 없음**, 요청사항 "직접입력" 선택 시만 메모 필드 |
| S20 | 마무리 | 탈퇴 페이지: 동의 체크 전 버튼 disabled·확인 다이얼로그까지(**확정 금지**). 정적 5종+404 렌더 |
