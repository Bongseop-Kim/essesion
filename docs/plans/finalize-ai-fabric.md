# AI 실사화 finalize — 캡슐 구현

2026-08-20 논의로 확정된 방향을 실행한다: finalize의 고객 대면 산출물을 절차적
질감 합성에서 **AI 실사화**로 교체한다. 산출물은 실사 이미지 2장이다.

- **넥타이 실사**: 미리 준비한 **고정 스튜디오 베이스 사진**(흰 셔츠 + 매듭 잡힌
  무지 회색 넥타이, `apps/worker/src/worker/render/assets/photo/tie-base.png`,
  1024×1536)의 **넥타이 영역만** 사용자 디자인으로 교체한다(마스크 인페인팅).
  셔츠·매듭·조명·주름은 AI가 창작하지 않고 사진에서 온다 — 품질 하한이 올라가고
  모든 완성본의 구도·조명이 일관된다.
- **원단 실사(접사)**: 결정론 타일을 3×3으로 깔아 편집 입력으로 준다.

두 편집 모두 참고 이미지로 **결정론 렌더**(디자인의 색·모티프·배치)와
**직조 실물 사진**(사용자가 고른 짜임에 해당하는 `render/assets/fabric/` 에셋)을
함께 넘긴다 — "이렇게 짜인 것처럼"의 기준을 프롬프트 텍스트가 아니라 사진으로
준다. 실의 짜임(weave)은 실사화 전에 사용자가 **고정 옵션 피커**로
선택한다(자유 입력 없음).

이 문서는 worker 내부의 새 finalize 캡슐만 다룬다. 화면 흐름·api 스키마·과금·
명세 갱신은 `finalize-ai-cutover.md`가 담당하며, 이 문서가 먼저다.

## 왜 필요한가

- 현행 finalize(`apps/worker/src/worker/render/fabric.py:72` 이하)는 실사 weave
  PNG를 multiply 합성하는 방식이라 "질감 오버레이 깔린 프린트"가 표현력의 천장이다.
  실의 교차, 이방성 광택, 배경과 모티프의 직조 차이를 표현하지 못한다 (2026-08-20
  사용자 실물 관찰 — 실측 문서는 없음).
- 타일은 기계가 소비하는 생산 사양이 아니라 **원단 디자이너(사람)에게 넘기는
  참고물**이고, 직조 실현 가능성 판단은 사람의 영역이다. 따라서 고객 대면 이미지에
  seamless·바이트 결정론 계약을 요구할 이유가 없다. 결정론이 계속 필요한 곳은
  "의도의 정본"인 intent JSON + 결정론 렌더까지다.
- 목표 품질 기준: 범용 이미지 모델 구독(GPT)으로 뽑는 넥타이 원단 이미지 수준.
  이 수준에 못 미치면 서비스의 설득력이 없다는 것이 이 개편의 출발점이다.

## 범위 밖 (non-goals)

- 사람 착장 샷·스타일링 컷 — 산출물은 넥타이 단독 + 원단 접사 2장뿐.
- 절차 렌더 경로의 제거 — 제거하지 않는다. AI 참고 이미지 생성기이자 정본
  타일 생성기로 존속한다.
- store 화면·api 응답 스키마·과금 단가·명세 갱신 — `finalize-ai-cutover.md`.
- intent 스키마 변경 — weave 선택은 현행 finalize 요청 파라미터
  (`apps/api/src/api/domains/design/router.py:486` `KNOWN_WEAVES` 범위)를 그대로 쓴다.
- **짜임 피커 신설 — 불필요**. `apps/store/src/features/design/ui/finalize-dialog.tsx`에
  「제작 방식」(날염·선염) + 「원단 짜임」(날염 2종 / 선염 7종, 무효 조합 검증 포함)
  SelectBox가 이미 있다. 이 플랜은 그 선택값을 프롬프트 재료로 소비할 뿐이다.

## 실행 조건

- OpenAI Images **편집 엔드포인트(`/images/edits`)가 현행 어댑터 모델
  (`apps/worker/src/worker/adapters/gpt_image.py:33`, `gpt-image-2`)에서
  ① 다중 입력 이미지(`image[]`)와 ② 마스크 인페인팅(`mask`)을 지원하는지
  공식 문서로 확인**한 뒤 시작한다. 마스크 극성(투명/불투명 중 어느 쪽이 교체
  영역인지)도 같은 문서에서 확정한다 — 2항의 마스크 제작 방향이 여기에 걸린다. 미지원이면 지원되는 최신 모델로 핀을 바꾸고,
  마스크가 어떤 모델에서도 불가하면 베이스 넥타이를 크로마키 색으로 바꾼 사진 +
  프롬프트 지시("초록 넥타이를 교체")로 폴백한다(기각 대안 참조).
  단가·파라미터를 기억으로 쓰지 말 것 — 요금표·API 레퍼런스 확인이 선행 조건이다.
- `OPENAI_API_KEY` 필요(유료 호출, finalize 1회당 편집 2회). 키 없는 환경의
  동작은 아래 7항(503)을 따른다.

## 절차

1. **어댑터에 편집 호출 추가** — `apps/worker/src/worker/adapters/gpt_image.py`의
   `GPTImageHTTPClient`에 이미지 편집 메서드를 추가한다(입력 이미지 목록 +
   선택적 마스크 + 프롬프트 → PNG). 기존 재시도 루프(지수 백오프, 429/5xx),
   base64 디코딩 검증, 10MB 상한, `log_provider_usage`(`adapters/__init__.py:19`)를
   그대로 재사용한다. 근거: 현행 클라이언트는 `/images/generations` 생성 전용이라
   편집이 불가능하다.
2. **베이스 사진 + 넥타이 영역 마스크 (신규 에셋)** — 베이스 사진은
   `render/assets/photo/tie-base.png`(2026-08-20 준비 완료, 무지 회색 넥타이 —
   교체 영역에서 무늬가 새어 나올 게 없고, 매듭·주름의 음영은 남아 모델의 입체감
   참고가 된다). **넥타이 영역 마스크는 이 사진 위에 한 번만 수작업으로
   그려**(매듭 포함, 셔츠 제외) `tie-base-mask.png`로 같은 디렉토리에 둔다 —
   베이스가 고정이므로 마스크도 영구 재사용, 런타임 세그멘테이션 불필요.
   마스크 경계는 넥타이 윤곽보다 1~2px 안쪽으로(셔츠 침범 방지).
3. **결정론 넥타이 렌더 신설 (참고 이미지용)** — worker에 타일 → 넥타이 목업
   Pillow 합성기를 추가한다: 타일 반복 채움 → 넥타이 실루엣 마스크 → 그림자.
   역할은 편집의 베이스가 아니라 **패턴의 배치·스케일·색을 알려주는 참고
   이미지**다. store `TieCanvas`(`packages/shared/src/components/tie-canvas.tsx`)와
   같은 기하로 만들어야 고객이 캔버스에서 본 미리보기와 실사 결과의 패턴 스케일
   감각이 일치한다. 기하 상수(tie-canvas.tsx에서 그대로 가져올 것): 아트 박스
   비율 316:687.72(= 316×864/397), 마스크 박스 top 8.4347% · height 87.244%,
   타일 반복 배율 `background-size = tileFraction(0.16) × tileScale × 100%`
   (tileScale = intent `canvas.tile_mm` / 48). 에셋 `tie.svg`(실루엣 마스크)·
   `tie-shadow.png`(397×864)를 store `public/images/`에서 worker 에셋으로 복제한다.
4. **편집 입력 구성** — 두 편집의 입력을 다음과 같이 짠다.
   - 넥타이 실사: `[베이스 사진(마스크 대상), 결정론 넥타이 렌더(3항), 직조
     사진]` + `tie-base-mask.png`. 프롬프트 취지: "마스크 영역의 넥타이를 두 번째
     이미지의 디자인으로 교체하고, 세 번째 이미지처럼 직조된 질감으로."
   - 원단 실사: `[결정론 타일 3×3, 직조 사진]` (타일링은 `render/weave.py:39`
     `tile_to` 재사용). 프롬프트 취지: "이 디자인 그대로, 두 번째 이미지처럼 직조된 원단
     접사 사진으로."
   - 직조 사진은 사용자가 고른 weave의 `render/assets/fabric/{weave}.png`를
     재사용하되, 원본이 2.5~7.6MB 스캔이므로 **참고용으로 중앙 크롭 + 축소한
     사본을 미리 만들어 둔다**(업로드 크기·비용 절약, 매 요청 리사이즈 방지).
5. **프롬프트 빌더** — finalize params(production.method, 기존 피커가 보내는 weave,
   palette 슬롯 색)에서 넥타이용·원단용 프롬프트 2종을 조립한다. 피커의 한국어
   라벨·설명(예: 자카드 = "무늬가 도드라지는 입체 짜임")이 프롬프트 문구의 1차
   재료다 — UI 문구와 프롬프트가 갈라지지 않게 매핑 표를 한 곳에 둔다. 공통
   불변 지시: "패턴·모티프 형태·색 변형 금지, 셔츠·매듭·조명은 그대로."
   프롬프트는 캘리브레이션 대상이므로 상수 한 곳에 모은다.
6. **캡슐 함수와 삼중 산출물** — 새 파이프라인: 결정론 렌더 2장 + 고정 에셋 →
   어댑터 편집 2회 → 출력 PNG 검증(디코딩 가능, 크기 상한). finalize 라우트
   (`apps/worker/src/worker/api/routes.py:1129`)는 **세 파일을 업로드**한다:
   넥타이 실사 + 원단 실사(기존 `fabric/{sha256[:16]}.png` 프리픽스) + 정본 타일
   (신규 `tile/{sha256[:16]}.png`; 정본 타일 = 현행 `render_fabric` 출력 그대로 —
   질감 합성이 포함된 결정론 렌더이며 AI 참고 이미지와 동일 바이트), 응답
   `result`에 `tie_object_key` +
   `fabric_object_key` + `tile_object_key`. 근거: 고객 설득물은 실사 2장,
   디자이너 인수물은 타일 — 역할이 다른 산출물을 모두 남긴다(2026-08-20 확정).
7. **오류 시맨틱** — 키 미설정 `AdapterNotConfigured` → 503(어댑터 하드 에러 패턴
   유지, `adapters/__init__.py:1-8` 설계 의도), 업스트림 4xx(콘텐츠 거절 등) →
   422, 5xx·타임아웃 → 5xx. 편집 2회 중 1회만 성공한 경우도 실패로 취급한다
   (부분 성공 상태를 만들지 않는다 — api의 단일 환불 지점
   `apps/api/src/api/domains/design/router.py:1997`이 그대로 작동해야 한다).
8. **테스트** — worker finalize 동기 계약 테스트를 어댑터 mock 주입으로 재작성.
   결정론 렌더 단계(타일·넥타이 합성)의 골든 픽셀 테스트는 **유지·추가**한다
   (참고 이미지·정본으로서 여전히 결정론) — 계약 문구 재서술은 cutover 문서의
   명세 항목.

## 검증

- 어댑터 mock으로 `uv run pytest apps/worker/tests/test_fabric.py` 및 finalize
  계약 테스트 통과. 넥타이 합성기 골든 추가분 통과.
- 실호출 캘리브레이션: 골든 intent 3~5종(`apps/worker/tests/golden/json/`) ×
  weave 옵션 2~3종으로 실제 생성해 육안 평가. 성공 기준: (a) 팔레트 색 유지,
  (b) 모티프 형태 유지, (c) 선택한 weave가 두 이미지에서 시각적으로 구분됨,
  (d) 넥타이 실사에서 베이스 사진의 셔츠·매듭·조명이 유지되고 마스크 경계가
  자연스러움, (e) 질감이 절차 렌더 대비 명백히 우위 — GPT 구독으로 뽑은 대조
  이미지와 나란히 놓고 판단. 미달이면 참고 이미지 조합(넥타이 렌더 생략, 직조
  사진 생략, flat 래스터 교체)을 바꿔가며 재평가.

## 실패 모드

코드 완성을 품질 완성으로 착각하는 것 — 파이프라인이 돌아도 출력이 "GPT 구독
수준" 기준에 미달이면 이 플랜은 미완성이며, cutover로 넘어가면 안 된다.

## 기각한 대안

- **절차 렌더 고도화(모티프별 weave 파라미터·sheen 수공예)**: numpy 없는 Pillow
  합성으로는 사진 품질 천장을 못 넘는다. AI가 그 역할을 대체. 재론 조건: AI
  비용·콘텐츠 정책이 서비스를 실질적으로 막을 때.
- **api에서 AI 호출**: 도메인 규칙("워커는 이미지 생성만") 위반. 과금은 이미 api가
  worker 호출 전에 차감하므로 worker 배치로 충분.
- **절차 렌더로의 silent 폴백**: AI 단가 기준 과금과 어긋나고 품질 저하를 은폐한다.
  어댑터 하드 503 패턴 유지.
- **AI로 seamless 타일 직접 생성**: 호스팅 API로는 토로이드 연속성을 강제할 수
  없다. 타일은 절차 렌더가 계속 담당.
- **넥타이 장면 전체를 AI가 생성(베이스 사진 없이 img2img)**: 셔츠·매듭·조명을
  매번 창작해 편차가 크고 완성본 간 일관성이 없다. 고정 베이스 + 영역 교체로 대체
  (2026-08-20 결정).
- **무늬 있는 베이스 사진(스트라이프 등)**: 기존 무늬가 출력에 새어 나오고, 사진
  속 직조 질감이 사용자가 고른 짜임과 충돌한다. 무지 회색으로 확정.
- **크로마키 녹색 베이스**: 마스크 인페인팅이 있으면 색으로 영역을 알려줄 필요가
  없고, green spill이 경계에 남을 위험만 있다. 마스크 미지원 모델로 폴백해야 할
  때만 재론(실행 조건 참조).
- **weave 자유 텍스트 입력**: 프롬프트 인젝션·품질 편차·과금 예측 불가.
  피커 고정 옵션(KNOWN_WEAVES 범위)만 허용.
