# 디자인 정확도 — 미실행 후속과 조건부 항목

2026-09-09 [정확도 평가 라운드](../reviews/design-accuracy-baseline-2026-09-09.md)에서 **실행하지 않은 것만** 남겼다.
기준 확정·변별력 보강·반복 측정·대화 평가는 끝났고, 그 과정에서 제품 결함 두 개를 고쳤다.
1번만 지금 바로 실행 가능하고, 나머지는 **조건이 갖춰질 때까지 실행하지 않는다.**

## 실행 조건

- 유료 호출은 `--confirm-live`와 명시적 동의가 있을 때만. 없으면 기다린다.
- 코퍼스 문장·조건 변경은 사람이 확정한 뒤에만. 실패한 사례를 통과시키려고 조건을 고치지 않는다.
  기준값이 필요하면 엔진 안의 근거(예시 `size_ratio` 등)를 찾아 쓰고 출처를 적는다.
- 기준을 바꾸면 `revision`을 올린다 — 같은 revision의 수치만 비교한다.
- 2~4번은 **아래 트리거가 실제로 관측된 뒤에** 연다. 트리거 없이 열면 근거 없는 변경이다.

## 1. 카탈로그 grounding 평가 (지금 실행 가능)

근거: 코퍼스의 원·별은 fixture symbol을 직접 넘겨 채점하므로 **검색 경로를 전혀 타지 않는다.**
"고양이를 넣어줘"가 어떤 그림을 고르는지는 한 번도 측정하지 않았다.

- 실제 카탈로그를 쓰는 소수 사례로 subject 일치와 근사 매칭 경고(`motif grounded only approximately`)
  발생 여부를 판정한다. 조건은 intent에서 확인 가능한 것만 건다.
- 모티프 생성(GPT Image)은 호출하지 않는다 — 검색·근사 매칭까지만 본다.
- 이 사례들은 fixture 모티프를 쓰지 않으므로 `input_motif_ids`를 비우고, 채점 대상 사실도
  `motif.ids` 대신 선택된 motif의 subject가 된다 — 채점기에 새 사실이 필요한지 먼저 확인한다.

## 2. 지명색 어휘에 흰색·검정을 넣을지 (조건부)

**트리거**: 흰색/검정 바탕이 요청과 다르게 나온다는 사용자 보고나 로그가 쌓이면.

근거: 2026-09-09 측정에서 "흰 바탕" 요청이 10회 중 1회 `#103A40`으로 나왔다. 같은 형식이라도
표에 있는 색(네이비)은 10/10이다 — 원인은 모델이 아니라 **표에 흰색이 없다는 것**이다.
표에는 navy·burgundy·ivory·gold만 있고 ivory(#FFFFF0)는 있는데 white(#FFFFFF)는 없다.

- 넣는다면 `_NAMED_COLOR_TARGETS`에 한 줄이지만, 어휘가 늘면 오탐(색 아닌 문맥의 "흰")도 는다.
  넣기 전에 기존 배제 규칙(`_NAMED_COLOR_EXCLUDED_*`)이 새 어휘에도 도는지 테스트로 고정한다.
- 넣은 뒤 002를 10회 반복해 9/10 → 10/10을 확인하고, 흰색이 등장하는 다른 사례의 회귀를 함께 본다.

## 3. 곡선 bbox 정밀화 (조건부)

**트리거**: AI 생성(gpt_image) 모티프가 같은 크기 설정에서 작아 보인다는 실제 불만.

근거: 2026-09-09 실측에서 카탈로그·업로드 모티프는 선언 크기의 0.98~1.00을 채우는데
gpt_image 2건만 0.854·0.947이었다. 47건 중 45건이 1% 이내라 지금 고칠 이유가 없다.
고치면 기존 저장 모티프와 신규 모티프의 크기 기준이 갈리므로 **identity 이관 계획을 먼저 세운다.**

## 4. 산개 샘플러 교체와 개수 미달 문구 (조건부)

**트리거**: `scatter placed N of M` 경고가 실제 생성 로그에 쌓이면.

근거: 2026-09-09 기준 실모델 실행 60회 이상과 브라우저 실측에서 이 경고는 **0건**이다.
`count`는 목표치라는 계약(`worker-engine.md` §3)을 유지한다.

- 미달이 실제로 쌓이면 Bridson(간격·생성 효율)과 Weighted Sample Elimination(지정 개수)을
  오프라인 비교한다. 후자가 임의의 최소 간격과 지정 개수를 동시에 보장한다고 가정하지 않는다.
- 채택하면 기존 바이트가 바뀐다 — 저장 intent의 재현 경로를 먼저 정하고 명세를 함께 고친다.
- 고객 문구가 필요해지면 api 스키마 변경과 `pnpm codegen`을 동반한다.

## 검증

- 오프라인: `uv run pytest apps/worker/tests/test_design_accuracy.py apps/worker/tests/test_patch.py`.
- 수집·채점: `collect_design_accuracy.py --confirm-live` → `eval_design_accuracy.py --outputs …`.
  간헐적 실패가 의심되면 `--repeat N`으로 사례별 성공률을 낸다 — 1회 실행 통과율은 20% 실패도 못 본다.
- 결과에는 모델·프롬프트/컴파일러 revision·코드 SHA·반복 횟수·지연을 함께 싣는다.

**실패 모드:** 트리거 없이 조건부 항목을 열어 근거 없는 변경을 하는 것, 그리고 만점 통과율을
품질 보증으로 착각하는 것이다. 2026-09-09 결함 두 개는 모두 만점 상태에서 사례·반복을 늘려 나왔다.
