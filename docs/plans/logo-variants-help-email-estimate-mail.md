# 견적서 메일 — 남은 확인

로고·대표 메일·견적서 메일의 코드와 운영 SMTP 배선은 2026-11-18에 실행했다(결과와 결정 변경은
`docs/reviews/logo-light-help-email-estimate-mail-2026-11-18.md`). 이 문서에는 **배포 뒤 확인과 운영자 결정**만
남아 있다. 견적서 메일 코드가 main에 머지·배포된 뒤 실행한다.

이 플랜의 실패 모드: 견적서의 금액 표기(부가세 포함)를 추정인 채로 거래처에 내보내는 것. 1의 답을 받기
전에는 견적서 메일을 손님에게 알리지 않는다.

## 왜 필요한가

- 견적서의 금액 표기는 운영자가 쓰던 수기 견적서를 근거로 한 **추정**이다(아래 1).
- 실제 발송 경로(엔드포인트 → iCloud SMTP → 받은편지함)는 운영에서만 끝까지 확인할 수 있다. 로컬에서는
  DB가 필요한 테스트 3건을 돌리지 못했다.

## 범위 밖

- DMARC 정책 상향(`p=none` → `quarantine`). 발신이 정렬돼 있어 올려도 깨지지 않지만 여기서 하지 않는다.
- 견적서 PDF, 발송 이력 저장, 계측 이벤트. 기각 사유는 리뷰 문서와 아래 "기각한 대안".

## 실행 조건

- 견적서 메일 코드가 배포돼 `/readyz`의 capabilities에 `mailer`가 보여야 한다. 안 보이면 아직 배포 전이니
  기다린다.

## 절차

1. **운영자 확인 (견적서 내용)** — 답이 다르면 `apps/api/src/api/domains/orders/estimate.py`와
   `docs/api-spec/domains.md` §7을 함께 고친다.
   - 스토어의 주문 제작 예상 금액이 **부가세 포함**인가. 지금 견적서는 포함으로 보고 공급가액·세액을 나눈다.
   - 자동 발송 견적서에도 **세금계산서 입금 계좌**를 싣는가. 수기 견적서를 따라 실어 두었다. 사이트 결제
     대신 계좌로 바로 입금하는 고객이 생길 수 있다.
   - 공급자 **업태**가 "도소매"가 맞는가(수기 견적서 그대로).
2. **도메인 전환 PR #112와의 충돌** — `apps/store/src/pages/home/index.tsx`의 구조화 데이터 `logo` 줄을
   양쪽이 고친다(#112는 주소를 `.shop` → `.com`으로, 이 작업은 파일명을 `logo-light.png`로). 나중에 머지되는
   쪽에서 충돌이 나면 `https://essesion.com/logo/logo-light.png`로 합친다.

## 검증

- `/readyz`의 capabilities에서 `mailer`가 `real`(SMTP 값은 2026-11-18에 넣어 두었다).
- 배포 뒤 운영자 계정으로 `/custom-order`에서 Gmail·네이버 메일 두 곳에 발송한다.
  - 받은편지함 도착(스팸함 아님), 보낸 사람 `help@essesion.com`, 원본에 `dkim=pass`·`dmarc=pass`.
  - 첨부 `견적서_영선산업_<날짜>.xlsx`의 합계가 화면 금액과 같고 공급가액 + 세액 = 합계.
  - 윈도우 엑셀과 휴대폰 메일 앱 미리보기에서 표·글꼴이 깨지지 않는다(2026-11-18에는 맥 미리보기로만 확인).
- 같은 계정으로 6번 연속 → 6번째에 "견적서 메일 요청이 너무 많습니다" 안내.
- 헤더 로고: store·admin의 흰 헤더에 검정 글자만 보이고 사각형 테두리가 없다. 모바일 폭에서도 획이
  뭉개지지 않는다.
- CI에서 `apps/api/tests/test_estimate_email.py`의 엔드포인트 3건 통과(로컬에서는 Docker가 꺼져 있어 돌리지
  않았다).

## 되돌리는 법 / 상향 신호

- 견적서 메일 끄기: `api_extra_env`의 `SMTP_USERNAME`을 비워 apply하면 Unavailable로 떨어지고 버튼은 503
  문구를 보여 준다(코드 배포 불필요). 완전히 빼려면 store의 버튼을 지운다.
- 앱 암호 유출 의심: account.apple.com에서 그 앱 암호를 폐기하고 새로 만들어
  `gcloud secrets versions add icloud-smtp-password`로 새 버전을 넣은 뒤 api를 재배포한다(`infra/README.md` 시크릿 값 주입).
- 메일 수신: iCloud Mail이 장애로 수신을 멈추면 DNS가 Cloudflare에 있으므로 MX를 다른 사업자로 바꾼다
  (TTL 3600). 사이트의 주소(`help@essesion.com`)는 그대로 둔다.
- 상향 신호:
  - iCloud 발송 거부(5xx)·스팸함 도착이 반복 → 트랜잭션 메일 서비스로 교체 검토(`mailer.py`만 바꾼다).
  - 전체 하루 200통 상한에 닿음 → 한 계정·한 수신자 반복이면 수신자를 계정 메일로 고정하고, 정상 수요면
    상한과 발송 수단을 다시 정한다. 한도는 iCloud 하루 1,000통
    ([Apple 102198](https://support.apple.com/en-us/102198))의 1/5로 잡았다.
  - 반송 메일(주소 오타)이 `help@` 받은편지함에 쌓임 → 입력 창에 주소 재확인 문구 추가.

## 기각한 대안

- **견적서를 메일 본문(HTML)으로**: 처음 플랜이었으나 거래처 결재에는 파일이 필요하다(2026-11-18 운영자
  결정). 재론 조건 없음.
- **견적서 PDF**: 엑셀은 거래처가 그대로 고쳐 쓸 수 있고 수기 견적서도 엑셀이었다. "PDF로 달라"는 요청이
  실제로 들어오면 재론.
- **비로그인 공개 발송**: 임의 주소로의 대량 발송 통로가 된다.
- **수신자를 계정 메일로 고정**: 가장 안전하지만 메일이 없는 소셜 계정이 못 쓰고, 결재 담당자 주소로 바로
  보내려는 용도와 어긋난다. 남용이 보이면 재론(상향 신호).
- **클라이언트가 금액·라벨 문구를 보내고 서버는 그대로 싣기**: 우리 명의 문서에 조작된 금액·임의 문구가
  실린다.
- **`email-validator` 추가(`EmailStr`)**: 형식 검사만 얻는다. 정규식으로 ASCII 단일 주소만 받는다.
- **계측 이벤트 추가**: 버튼·"보내기" 클릭은 PostHog autocapture가 잡고
  (`apps/store/src/shared/lib/product-analytics.ts`에서 꺼져 있지 않고 `/custom-order`는 마스킹 경로가 아니다,
  2026-11-18 확인) 발송 수는 api 로그에 남는다. "견적서 수령 → 주문" 전환을 지표로 쓰게 되면 재론.
- **로고를 SVG 한 장·CSS 반전·`logo-dark.png` 개명으로**: PNG 한 장 추가로 끝났다. 로고가 놓이는 배경이 3종
  이상으로 늘면 재론.
- **Google Workspace·네이버웍스**: 월 과금. 직원이 생겨 공용 사서함·관리 콘솔이 필요해지면 재론한다.
- **Cloudflare Email Routing + Gmail 발신**: Gmail "다른 주소에서 보내기"가 2027-01에 제거된다
  ([Google 공지](https://support.google.com/mail/answer/17101213?hl=en)). 재론 조건 없음.
- **Zoho Mail 무료·Purelymail(연 $10)**: iCloud+를 이미 내고 있어 추가 가입·비용이 불필요. iCloud 발송이
  거부되기 시작하면 재론한다.
