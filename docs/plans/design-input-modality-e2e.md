## 2. 실행 원칙

- **후보 수는 기본 1** — 생성이 동기 블로킹 POST(수십 초)이므로 기능 확인에 다양성이 필요한 시나리오(S8)만 4로 올린다.
- 시나리오마다 **새 세션**(새로 만들기)에서 시작. 이어가기가 논점인 경우만 예외로 명시.
- 모든 입력 기능은 컴포저의 **"옵션 더보기(＋)" 토글 안**에 있다. 토큰 잔액 표시도 이 패널 안에만 있다.
- 공통 관찰(모든 실행): ① 실행 전후 토큰 잔액 델타 ② 결과 plan에 설정이 실제 반영됐는지(화면 + `/seamless-logs` 교차) ③ Store·Admin 콘솔 오류/page error 0건 ④ 경고 노출의 적절성.
- 판정: PASS / WARN(동작하나 품질·일관성 문제) / FAIL. 별도로 개선 관찰을 **기능 결함 / UX·기획 / 코드** 3버킷으로 수집.
- 파일 첨부 자동화: 사진 첨부 input은 접근자가 없어 `input[type=file][multiple]` 구조 셀렉터 사용. SVG는 `getByLabel("SVG 모티프 파일 선택")`.

## 3. 시나리오

### S0 — 앵커 (환경 정상 확인)

텍스트 프롬프트 1회(예: "네이비 바탕에 작은 도트 패턴", 후보 1). 성공·토큰 5 차감·로그 기록 확인. 실패하면 환경 문제부터 해결하고 진행.

### S1 — 사진 첨부 (참고 방식 4종)

| 케이스 | 절차 | 기대 |
|---|---|---|
| S1-1 자동 판단 | 컬러 사진 1장 첨부(기본값 유지) + 프롬프트 | 성공, 사진 특성이 결과에 어떤 식으로든 반영 |
| S1-2 색감·분위기 | ChatGPT 컬러 이미지 첨부 → 칩 메뉴에서 변경 | 결과 팔레트가 사진 색감과 근접 |
| S1-3 모티프 형태 | logo.png, 참고 방식=모티프 형태 | Recraft 벡터화로 로고 형상 모티프 반영(선행 플랜 R2와 동일 경로 — 여기선 회귀 확인 1회) |
| S1-4 배치·구도 | 격자·사선 등 구도가 뚜렷한 사진 | 배치 구조 반영 |
| S1-E 엣지 | 5장 초과 첨부 시도, 10MB 초과 파일 | 상한 안내(스낵바), 업로드 거부 문구의 명확성 |

관찰: purpose 미변경 시 "자동 판단"이 실제로 무엇을 골랐는지 로그에서 확인 가능한가(사용자에게 보이는가) — 기획 관찰.

### S2 — SVG 모티프

1. 샘플 SVG 임포트 → **확인 단계 없이 즉시 저장+선택되는 현행 UX** 관찰(의도 여부 기획 판단).
2. 프롬프트 없이(모티프만으로 제출 가능 — `canSubmitWithoutPrompt`) 생성 1회, 프롬프트와 함께 1회.
3. 기대: 업로드한 캐릭터 형상이 패턴 모티프로 사용. 원본 색(주황 배경 포함)이 어떻게 처리되는지 기록 — 배경 사각형이 모티프에 포함되는 SVG인데 정규화가 이를 어떻게 다루는지가 관찰 포인트.
4. 엣지: 2MB 초과 SVG(스크래치에 생성) 거부 문구.

### S3 — 텍스트 모티프

1. 모달에서 "잇선" 입력 → 글꼴 나눔고딕/나눔명조 전환, 굵기 400/700, 자간 조정 — 미리보기(400ms 디바운스) 반영 확인.
2. 저장 → 내 모티프에 추가·선택 → 생성 1회, 텍스트 형상 반영 확인.
3. 엣지: 20자 초과, 허용 외 문자(이모지·한자) 거부 문구.

### S4 — 사진 모티프

1. 모달에서 logo.png 업로드 → 배경 제거 on/off, 단순화 low/high, 색상 수 1·6 조합 3~4회 미리보기 — 결과 차이와 `background_confidence` 경고 노출 관찰.
2. "자동 분리·벡터화" → "내 모티프에 저장" 2단계 CTA 흐름의 자연스러움 관찰(기획).
3. 저장 → 선택 → 생성 1회, 반영 확인.
4. 보조: 컬러 사진(ChatGPT 이미지)으로 1회 — 사진 유형별 벡터화 품질 기록.

### S5 — 내 모티프 (라이브러리·슬롯 회계)

1. 내 모티프 모달: S2~S4에서 저장한 모티프 목록 확인, 2개 선택 → 3번째 선택 시도 → 상한 안내.
2. **합산 회계**: 모티프 1개 선택 + 사진 첨부(참고 방식=모티프 형태) 1장 → 추가 모티프 선택 시도가 막히는지(직접 선택+purpose=motif 사진 합계 2 제한).
3. 모티프 2개 동시 사용 생성 1회 — 두 형상 모두 반영.
4. 삭제 → 목록 갱신 → 새 세션에서 삭제된 모티프가 안 보이는지.

### S6 — 색상 설정

1. fixed 2색(HEX 직접 입력, 예: `#000080`/`#F5F5DC`) → 생성 → **두 색 모두 결과에 가시적**인지(컴파일러가 전 색 가시성을 강제) + plan `colors` 일치.
2. fixed 5색(picker 사용) → 생성 → 반영 확인.
3. **대표 색상 추출**: 컬러 사진 첨부 후 추출 → 추출값의 타당성 → 그대로 생성.
4. fixed 상태에서 다시만들기(reroll) — colorway가 의도적으로 drop되는 동작이 사용자 관점에서 자연스러운지 관찰.
5. 엣지: 동일 색 2개 입력 시도(서로 다른 색 2~5 제약), 잘못된 HEX.

### S7 — 패턴 설정 (4축)

1. 축별 단독 non-auto 1회씩: 모티프 크기(크게), 밀도(성기게), 배열(격자→사선 등 1개), 방향(대각 등 1개) — 각 생성 후 plan 대조. auto 대비 차이가 시각적으로 식별되는지.
2. 4축 동시 지정 1회 — 상충 없이 모두 반영되는지, 무시된 축이 있으면 경고가 뜨는지.
3. 관찰: 축 라벨·옵션 명칭이 결과와 직관적으로 대응하는가(기획).

### S8 — 통합·refine (후보 4)

1. 새 세션, 후보 4: 내 모티프 1개 + 고정 팔레트 3색 + 패턴 2축 + 프롬프트 동시 지정 → 생성 → 4후보 전부 제약 준수 확인.
2. 이어서 refine 발화("모티프만 다른 것으로 바꿔줘" 등 1회) → **설정(팔레트·패턴 제약)이 유지**되는지, 선택 후보 기준으로 진행되는지(7/29 계약 회귀).
3. 다시만들기 1회 — seed 변경 외 설정 유지.

### S9 — 실사화·내려받기·부가 기능

1. **실사화**: 후보 선택 → 실사화 다이얼로그(제작 방식·원단 짜임·해상도) → 제출 → 인라인 실행이므로 폴링(2.5s)으로 succeeded 도달 → 결과 타일·내려받기·"주문 제작하기" 진입 확인. 24시간 쿼터 잔여 표시 관찰.
2. 실사화 **취소**: 1건 제출 직후 "취소하고 횟수 되돌리기" — 쿼터 복원 확인(실패·취소는 카운트 제외 설계).
3. **내려받기**: export 다이얼로그에서 포맷·해상도 옵션 → 다운로드 성공, "토큰 미사용" 문구 확인.
4. **아이디어**: 문맥(첨부·모티프·설정) 있는 상태에서 4개 생성 → "기존 문장 바꾸기"/"뒤에 추가" 동작, 무과금 확인.
5. **내 세션 / 내 완성본**: 목록 표시, 세션 열기·삭제(확인 다이얼로그), 완성본 무한스크롤.
6. **미리보기**: 타일/넥타이 전환, 후보 클릭=조회 스테이징 → "이 이미지로 편집" 커밋(7/29 최종 계약 스팟 체크).

### S10 — 비로그인·온보딩 (경량)

1. 로그아웃(또는 시크릿 컨텍스트) → `/design` 직접 진입: 빈 상태 화면의 안내 적절성(현재 쿼리가 전부 인증 게이트 뒤라 **무엇이 보이는지** 자체가 관찰 대상).
2. 사진 첨부 등 액션 시도 → "로그인이 필요합니다" 다이얼로그 → 로그인 → `/design` 복귀.
3. localStorage `design:onboarding:v1` 제거 후 진입 → 온보딩 다이얼로그 내용이 실제 기능(＋ 패널 뒤에 숨은 입력들)을 충분히 안내하는지 — 기획 관찰.

## 4. 사전 식별된 개선 관찰 후보 (실행 중 실태 확인해 기록)

코드 조사에서 이미 보인 것들. 테스트에서 실제 영향을 확인하고 리뷰 문서에 판정과 함께 기록한다.

- **UX·기획**: 토큰 잔액·회당 비용이 "옵션 더보기" 패널 안에만 표시(접힌 기본 상태에선 비용 인지 불가). 모든 입력 기능이 ＋ 토글 뒤에 숨어 발견성 낮음(온보딩이 커버하는지 S10-3에서 판정). 이름 중복 버튼("내려받기" 4곳 등)의 혼동 여부.
- **코드(접근성)**: 사진 첨부 `<input type="file">`에 aria-label 부재(SVG 쪽엔 있음) — 한 줄 수정감.
- **코드(정리)**: 미사용 엔드포인트 `branch`·`motifs/candidates`·`motifs/generate`(선행 플랜 §4와 합산), 세션 Recraft 예산 미적용, worker 503 분기 실질 미작동 경로.
- **자동화 부채**: Playwright config가 파일명 고정 매칭이라 디자인 스펙 추가 불가 + webServer에 worker 부재 — 이번 수동 검증에서 안정 셀렉터가 확보되면 Playwright 이관 플랜을 후속으로.
