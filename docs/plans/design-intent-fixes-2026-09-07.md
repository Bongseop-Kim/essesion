# 디자인 의도 보존 수정 제안 — 2026-09-07

**상태: 제안만 작성, 미실행.** [Aside 실행 기록](../reviews/design-page-aside-2026-09-07.md)의 실제 실패를 기준으로 작성했다. 고객이 바꾸라고 한 요소만 바꾸고, 수행할 수 없는 요청은 구체적으로 설명하는 것이 목표다. 아래 순서로 작은 수정부터 적용한다.

## 왜 필요한가

실측에서 초록 바탕이 아이보리로 덮였고(D1), 사자가 없는 디자인의 꽃을 확대하면서 사자를 수정했다고 응답했다(D2·D3). 엇갈림 전환은 요청하지 않은 밀도 증가를 만들었다(D4). 모티프별 회전·밀도·부분 재색은 현재 계약으로 표현할 수 없어 거절됐다(D5). 첫 로고 추가는 의도보다 조밀했다(D6).

D1은 로컬 함수 단독 실행으로도 재현했다. D3·D4는 실제 patch와 결과 수치로 원인을 좁혔다. D2의 검색 후보 선택 이유와 후처리 전 모델 원문까지는 확보하지 못했으므로, 그 부분의 원인은 추정으로 남긴다. 증거는 실행 기록의 `steps.json`·`diagnostics.jsonl`과 스크린샷을 사용한다.

기존 2026-07-30 입력 모달리티 리뷰의 폐기 UI 개선과 2026-08-21 화면 다듬기 작업은 제외한다. 아래는 현재 구조에서 새로 재현된 문제에 한정한다.

## 범위 밖

페이지 재설계, 새 편집 프레임워크·에이전트 루프 도입, 생성할 때마다 추가 이미지 검수 API 호출, 엔진의 seamless 보장 제거는 하지 않는다. 결제·인증 자동 재시도 정책도 이 변경에 섞지 않는다.

## 실행 조건

- `ARCHITECTURE.md`, [worker 계약](../api-spec/worker-pipeline.md), [모티프 계약](../api-spec/worker-motifs.md)을 읽고 시작한다. 프론트 안내를 수정할 때는 `packages/shared/AGENTS.md`를 먼저 읽는다.
- 외부 API 없이 D1·D3·D4의 실패 입력을 회귀 테스트로 고정한다. 해당 코드가 변경되어 재현이 사라졌으면 먼저 최신 동작을 확인하고 중복 수정하지 않는다.
- API 응답 또는 patch 계약 확장은 명세와 함께 바꾼다. API 스펙 변경 시 `pnpm codegen`으로 생성 클라이언트도 갱신한다. 모티프 색 불변 계약을 몰래 우회하지 않는다.
- 실제 Aside 재검증은 로컬 계정·잔액·provider 연결이 준비된 뒤 실행한다. 준비되지 않으면 유료 단계를 실행하지 말고 기다리며 로컬 회귀 검증부터 수행한다.

## 수정 순서

### 1. D1 — 바탕색을 잘못 덮는 근접색 추론부터 제거

**위치:** `apps/worker/src/worker/adapters/named_colors.py:110`, `:151`, `:180`.

색 역할을 단순 거리 16자 이내로 부여하지 말고 색과 바탕/줄의 직접 수식 관계를 우선한다. 인식하지 못한 색 표현 뒤에 바탕이 있으면, 다른 역할의 알려진 색을 끌어와 덮지 않고 모델이 지정한 바탕을 보존한다. 초록 한 단어만 어휘에 추가하는 것으로 끝내지 않는다. 다른 미등록 색에서도 같은 오류가 재발하기 때문이다.

**완료 기준:** `짙은 초록 바탕에 굵은 아이보리 사선 줄과 가는 금색 보조 줄…`에 대해, 바탕 `#14532D`를 가진 유효 plan이 정규화 후에도 같은 바탕을 유지한다. 아이보리/금색 줄과 기존 네이비 바탕 정상 사례는 보존한다. Aside S2 최초 요청에서도 초록 바탕이 실제로 보인다.

### 2. D3 — 편집 대상과 슬롯을 실제 모티프에 연결

**위치:** `apps/worker/src/worker/engine/patch.py:242`, `apps/worker/src/worker/api/routes.py:626`, `apps/worker/src/worker/adapters/llm.py:221`.

현재 `composition_snapshot`은 모티프 이름·정체성을 빼고 크기 순서만 전달한다. 기존 모티프 레지스트리의 이름/설명과 요청 한정 슬롯 별칭을 읽기 전용 문맥으로 제공한다. patch가 모티프 정체성을 쓰거나 바꾸도록 허용할 필요는 없다. 대상이 없거나 둘 중 어느 것인지 확인할 수 없으면 임의로 첫 슬롯을 고르지 않고 변경을 거절한다.

**완료 기준:** 실제 꽃/잎만 있는 상태에서 `사자만 1.5배`는 꽃을 바꾸지 않는다. 사자/가지가 있는 상태에서 사자만 확대하고 가지는 보존한다. 슬롯 순서가 뒤집힌 경우에도 실제 대상을 선택한다. note가 실제로 적용하지 않은 작업을 했다고 말하지 않는다.

### 3. D2·D5 — 누락과 지원 불가를 구분해 안내

**위치:** `apps/worker/src/worker/adapters/llm.py:709`, `apps/worker/src/worker/adapters/motif_intent.py:61`, `apps/worker/src/worker/api/routes.py:647`, `apps/api/src/api/domains/design/router.py:358`, `:1605`, `apps/store/src/features/design/ui/canvas-notice.tsx:30`, `apps/store/src/pages/design/index.tsx:154`.

현재 첫 저작의 누락 감지는 `not plan.motifs`라 꽃/잎이 하나라도 있으면 사자 누락을 놓칠 수 있다. 기존 저작 호출·후보 메타데이터 안에서 요청 주제와 채택한 모티프의 대응을 기록하고, 일부 누락/근사 대체를 고객에게 알린다. “사자+꽃 가지”를 꽃과 잎 두 슬롯으로 쪼개어 모두 반영했다고 취급하지 않는다. 별도 비싼 모델 호출은 먼저 추가하지 않는다.

범위 거절은 신규 모티프 교체, 부분 재색, 레이어별 회전/밀도, 줄 사이 위치 미지원 등을 안전한 이유 코드로 구분한다. 코드별 짧은 한국어 안내를 표시한다. 위치나 부분 재색을 요청한 고객에게 피커에서 그림을 찾으면 해결되는 것처럼 안내하지 않는다. 원시 모델 note를 그대로 공개하기보다 검증된 코드에 대응하는 문구를 사용한다.

**명세 영향:** 공개 응답에 이유/누락 필드를 추가하면 `docs/api-spec/domains.md` §11과 `worker-pipeline.md` §5를 함께 갱신하고 codegen한다. 거절 무과금·이력 원복 계약은 유지한다.

**완료 기준:** S4 최초 결과에 사자가 없으면 누락을 명시한다. S1 위치 변경과 S4 꽃잎 재색/가지만 회전은 실제 지원 범위를 설명하며 디자인을 변경하지 않는다. 모티프 없는 S2의 `모티프는 넣지 마`를 새 모티프 추가 의도로 안내하지 않는지도 확인한다.

### 4. D4 — 배열 변경 시 기존 간격 보존과 seamless를 함께 검증

**위치:** `apps/worker/src/worker/engine/patch.py:482`, `apps/worker/src/worker/engine/constraints.py:73`, `apps/worker/src/worker/engine/placement.py:123`.

홀수 3을 짝수 4로 올리는 줄만 삭제하지 않는다. 반 칸 엇갈림의 경계 연속성이 깨질 수 있다. arrangement-only 요청은 기존 cell과 모티프 크기를 유지하는 반복 단위를 먼저 선택한다. 예컨대 상한 내에서 반복 단위를 확장하되 기존 길이를 유지하는 표현이 가능한지 검증한다. 기존 stripe/다른 레이어가 있으면 그것들의 시각 크기·밀도도 보존해야 한다.

간격 보존과 경계 조건을 함께 만족할 수 없다면 조정 전후 밀도와 이유를 알린다. `drop_axis`를 항상 column으로 고정하는 현재 동작도 유지 계약에 명시하고, 행/열 구분 지원은 필요할 때만 patch에 추가한다.

**완료 기준:** S3의 tile 48/cell 16/크기 9에서 엇갈림 전환 후 같은 화면 면적의 밀도가 증가하지 않는다. tile 경계 연속성을 동시에 확인한다. 상한에서 불가하면 묵시적 성공 대신 구체적 보정 안내가 남는다.

### 5. D6 — 첫 모티프 추가 기본값에 여백 확보

**위치:** `apps/worker/src/worker/engine/patch.py:608`의 `_first_motif_layer`.

현재 기본 크기 `tile×0.18`은 6분할 셀 `tile/6`보다 크다(S5: 8.64 > 8). 첫 추가에 한해 셀보다 충분히 작은 크기를 기본값으로 사용한다. 예를 들어 셀의 절반을 시작값으로 시각 검증한다. 이미 사용자가 정한 크기나 기존 모티프 교체 크기를 일괄 축소하지 않는다.

**완료 기준:** S5의 테스트 로고를 추가했을 때 로고 사이 여백과 가는 스트라이프를 식별할 수 있다. 이후 명시적 확대·크기 복원은 그대로 작동한다. SVG의 비대칭 형상은 보존된다.

### 6. D5 기능 확장 — 레이어별 배치와 부분 재색은 별도 계약으로 결정

**위치:** `apps/worker/src/worker/engine/patch.py:92`, `:465`, `apps/worker/src/worker/engine/intent.py:83`, `apps/worker/src/worker/engine/placement.py:65`.

1–5 적용 이후에도 고객 목표를 달성하려면 모티프 슬롯을 지정한 회전·밀도 patch, 기존 host/lane 또는 위상을 이용한 줄 사이 배치를 설계한다. 한 요청에 지정된 레이어만 바꾸고 다른 레이어는 보존하는 방식으로 최소 확장한다. 전역 배치 필드를 슬쩍 재해석하지 않는다.

**부분 재색은 별도 결정이 필요하다.** 현재 색이 모티프 identity에 포함되므로 저장된 모티프를 직접 변경하지 않는다. 색 변형을 지원하기로 결정하면 새 모티프를 만드는 경로와 소유권·content hash·이력 보존 계약을 먼저 정한다. 꽃잎/잎 같은 의미 영역은 단순 hex 치환과 같지 않다. 기존 SVG가 영역을 구분하지 못하는 경우까지 지원한다고 약속하지 않는다.

**완료 기준:** S4의 꽃 가지만 회전/성김 요청이 사자에 영향을 주지 않는다. 재색을 지원한다면 같은 꽃잎 형상만 아이보리로 바뀌고 잎·줄기·원래 이력은 보존된다. 지원하지 않기로 결정한 축은 3번 안내로 명확히 남긴다. 명세 갱신 전에는 구현하지 않는다.

## 검증

수정한 로직에 해당하는 기존 Python 테스트 파일만 골라 실패 사례를 추가·실행한다. 1번은 색 후처리, 2번은 대상 매핑, 4번은 홀수 격자+seamless, 5번은 첫 모티프 크기 사례를 검증한다. 프론트 안내를 바꾼 경우 그 안내 분기만 확인한다. 전체 Python 스위트는 로컬에서 실행하지 않는다.

API 변경 시 `pnpm codegen`, 문서·구조 변경 시 `pnpm architecture:check`, 변경 언어별 린트·타입체크를 실행한다. 마지막에 Aside로 해당 실패 단계만 다시 실행하고 전후 스크린샷·`current_intent`를 비교한다. 실제 모델의 주제 이해가 필요한 D2·D3은 순서가 뒤집힌 두 모티프 사례도 포함한다.

색 정규화 단독 재현 기록: 같은 S2 문장, 입력 colors `["#14532D", "#F2E9D5", "#C9A227"]`, ground index 0 → 현재 출력 `["#FFFFF0", "#F2E9D5", "#C9A227"]`. 이를 수정 후 첫 색이 유지되는 회귀 기준으로 사용한다.

## 되돌리는 법·상향 신호

seamless 경계 단절, 요청하지 않은 레이어 변경, 기존 이력의 모티프 색·형상 변형이 발생하면 해당 patch/정규화 변경만 되돌린다. 기존 저장 디자인을 일괄 재작성하지 않는다. 필요 시 실패 사례의 보정 안내부터 제공한다.

## 기각한 대안

- 프롬프트를 성공할 때까지 반복 변경: 사용자 요구 누락을 숨기므로 제외한다.
- 모든 디자인 생성에서 자동 AI 모티프 생성: 현재 명시적 생성·과금 경계를 깨므로 제외한다.
- staggered 짝수 제약만 제거: 경계 연속성을 검증하지 못하므로 제외한다.
- 모티프 symbol을 그대로 재색: identity·이력 불변 계약을 깨므로 제외한다.
- 미지원이면 전부 모티프 피커로 안내: 위치·부분 재색을 해결하지 못하므로 제외한다.

**실패 모드:** 기능 미지원을 실제 수정 버그와 섞거나, 한 단계의 수치만 맞추려고 다른 레이어와 seamless 보장을 훼손하는 것이다. 실행 후 결과를 `docs/reviews/`에 기록하고 완료한 제안은 이 문서에서 제거한다.
