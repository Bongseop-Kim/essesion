# 제작 기간 문구를 주 단위로 정리하고 포인트 주문 기간을 넣는다

포인트 주문 선택 항목 제한은 2026-11-18에 실행했다(`docs/reviews/custom-order-quote-flow-and-point-limits-2026-11-18.md`).
이 문서에는 그때 미룬 **제작 기간 문구**만 남아 있다. 서버와 무관한 스토어 문구 변경이다. 아래 표의 "제안" 세 줄을
운영자가 확인한 뒤 실행한다 — 확정된 두 줄만 먼저 고치면 한 화면에 "약 6~8주"와 "영업일 기준 21~28일"이 섞여 보이므로
기다린다.

이 플랜의 실패 모드: 확인받지 않은 기간을 사이트에 적어 손님과의 약속으로 만드는 것.

## 절차

지금 숫자(28~42·21~28·7~14)는 전부 7의 배수라 달력 주 단위로 잡은 값에 "영업일"이 붙은 것으로 보인다(추정 — 근거 문서는
없다). 글자 그대로 읽으면 실제 의도보다 길거나 짧게 읽히므로 "약 N~M주" 한 가지 표기로 통일한다. 영업일 숫자·"더 빨리 될 수
있다" 같은 덧붙임은 넣지 않는다(운영자 방침 2026-11-18: 사이트에는 넉넉하게, 문구는 단순하게).

| 주문 종류 | 지금 | 바꾼 뒤 | 확정 여부 |
|---|---|---|---|
| 일반 | 영업일 기준 28~42일 | 약 6~8주 | 운영자 확정 |
| 포인트(자수·필름) | 일반과 같게 나옴 | 약 3~5주 | 운영자가 "영업일 15~25일"로 정한 것을 주로 환산 |
| 재주문 | 영업일 기준 21~28일 | 약 4~6주 | 제안 — 실행 전 운영자 확인 |
| 원단 직접 제공 | 영업일 기준 7~14일 | 약 2~3주 | 제안 — 실행 전 운영자 확인 |
| 샘플 주문 | 28~42일("영업일" 없음) | 약 6~8주 | 제안 — 실행 전 운영자 확인 |

"제안" 세 줄은 지금 표기(영업일)를 주로 환산해 짧아지지 않게 올림한 값이다. 운영자가 다른 값을 주면 그 값으로 고친다.

고칠 곳(줄 번호는 2026-11-18 변경으로 밀렸으니 문구로 찾는다):

- `apps/store/src/pages/custom-order/index.tsx`의 `productionPeriod`: 포인트 분기를 맨 앞에 추가하고(포인트 + 재주문도
  포인트 기간) 나머지 값을 표대로 고친다.
- `apps/store/src/features/custom-order/ui/custom-order-service-guide.tsx`: 유의사항(괄호 안에 포인트 기간도 추가),
  재주문 FAQ, 히어로 알약("제작 약 6~8주"), 가격 섹션의 "제작 기간" 칸.
- 샘플: `apps/store/src/features/sample-order/ui/sample-order-service-guide.tsx`의 제작 단계 설명,
  `apps/store/src/pages/sample-order/index.tsx`의 "예상 제작 기간" 행.
- `docs/plans/home-redesign-yg3ke.md`의 "28~42영업일" 인용은 "출처 문구와 다르면 출처 값을 따른다"고 적혀 있어 고치지 않는다.
- 고친 뒤 `grep -rn "28~42\|21~28\|7~14" apps/store/src`가 비어야 한다.

실행한 뒤 결과를 위 리뷰 문서에 덧붙이고 이 문서를 지운다.

## 검증

- `pnpm lint && pnpm typecheck && pnpm --filter store test`
- 브라우저(store :3000 `/custom-order`, 사용자가 띄워 둔 경우만): 주문서의 "주문 전 확인해 주세요" 안내가 일반 "약 6~8주",
  "자수·필름"을 켜면 "약 3~5주"로 바뀐다. 정보 탭과 샘플 주문 페이지의 기간 표기가 표와 같다.
