# 프롬프트 모티프 의미 보존 플랜 (e2e-02 WARN 1)

> `docs/reviews/e2e-02-design-2026-08.md` D3b — scatter는 동백꽃 대신 붉은 별, lattice는
> 페이즐리 대신 무늬 없는 격자가 나왔다. 8/4 후속(`design-family-reverse-eval-2026-08-04.md`)이
> 고친 것은 **구조 재현**(P1 A+B 24/25)이고, 이 건은 그때 범위 밖으로 남긴 **카탈로그에 없는
> 소재** 문제다. 저작 모델 결함이 아니라 카탈로그 공백 + 공백을 사용자에게 알리지 않는
> 침묵 실패가 원인이다.

## 원인 — 침묵 실패 경로 2개

승인 카탈로그(71 subjects)는 동물·사물 중심이고 `paisley`·`camellia`가 없다
(`select distinct subject from motifs where status='approved'` 확인).

1. **무언 대체 (동백꽃 → 별)**: `/generate`의 grounding은 프롬프트 임베딩으로 τ=0.40
   (`worker/config.py:47`) 이상 후보 top-5를 LLM에 주고 LLM이 하나를 고른다
   (`motifs/resolver.py:338`). 요청 소재가 카탈로그에 없어도 τ만 넘는 이웃(별)이 선택되고,
   **선택이 성공이므로 어떤 경고도 내려가지 않는다**. 사용자는 잘못된 모티프를 5토큰 주고 받는다.
2. **무언 탈락 (페이즐리 → 맨 격자)**: 후보가 없으면 plan이 모티프 없이 저작된다. 이때
   피커 안내 사이드카는 `adapters/motif_intent.py:12`의 어휘
   (`모티프|무늬|도형|형태|로고|아이콘|꽃`)가 프롬프트에 있어야 발화하는데 **"페이즐리"는 이
   어휘에 안 걸린다**. D10(고래)은 "모티프"라는 단어 덕에 안내가 됐고, 페이즐리는 조용히
   무늬 없는 디자인이 됐다.

## 1. 재현·계측 — 임계값 근거 확보

- D3b의 두 프롬프트(동백꽃 scatter·페이즐리 lattice)를 로컬 워커로 재현하고
  `seamless_generation_logs`의 grounding 후보·similarity·선택 기록을 확인한다.
- 대체가 일어난 케이스의 similarity 분포로 "확신 매치" 임계(예: 0.55~0.60)를 정한다.
  카탈로그에 실제로 있는 소재(벌·별 등)의 정상 매치 분포와 겹치지 않는 값이어야 한다.

## 2. 무언 대체를 노랑 경고로 (코드)

- grounding에서 선택된 후보의 similarity가 확신 임계 미만이면 `GenerationWarning`을 추가한다.
  기존 경고 채널(`worker/warnings.py` 코드→한글 매핑 → store 캔버스 노랑 알림)을 그대로 탄다 —
  문구 예: "요청하신 그림과 꼭 맞는 무늬가 없어 비슷한 그림으로 만들었어요. 왼쪽 모티프에서
  바꿀 수 있어요."
- 디자인은 그대로 만든다(토큰 차감 유지) — 거절로 바꾸지 않는다. family·색·배치는 요청대로고
  소재만 근사치라, 결과를 보여주고 바꿀 길을 알려주는 쪽이 낫다.
- store는 warnings를 code+메시지로 이미 렌더하므로 프론트 무수정. worker 응답 스키마도
  기존 warnings 배열이라 api-client 재생성 불필요.

## 3. 카탈로그 miss 안내 어휘 확장 (코드)

- `_MOTIF_WORDS`에 텍스타일 단골 소재 명사를 추가한다: 페이즐리/paisley, 다마스크/damask,
  아가일/argyle, 헤링본/herringbone 등 — 소재이면서 그 단어 자체가 검색어인 어휘.
- 추가 어휘가 매치되면 `_subject`가 그 단어를 subject로 돌려주게 한다(현재는 "…로 바꿔"
  꼴과 "…꽃"만 추출) — 피커가 검색어까지 채운 채 열리게.
- 결과: 페이즐리 케이스가 D10과 같은 경로(패널 자동 확장 + 스낵바 + AI 생성 유도)를 탄다.
- "무늬"처럼 구성 축과 겹치는 단어는 넣지 않는다(줄무늬 제외 규칙 유지). 어휘별 유닛 테스트 추가.

## 4. 카탈로그 소재 보강 (운영)

- 우선 소재 목록은 추측하지 않는다 — admin의 저작 거절·motif_intent 로그와 모티프 검색
  0건 기록에서 실제 요청된 소재를 뽑는다. 페이즐리·동백꽃은 e2e로 이미 확인된 2건.
- 추가는 기존 경로로: Recraft 생성 → admin 승인 게이트(DA3 경로). **실 Recraft 호출은
  유료이므로 소재 목록 확정 후 건수를 정해 별도 승인받고 실행한다.**
- 시드로 넣을 경우(`scripts/seed_motifs.py`) 한글 tag를 반드시 함께 넣는다 — lexical 검색은
  exact-token 교집합이라 영어 subject는 한글 tag 없이 안 잡힌다(같은 파일 주석 참조).

## 5. 회귀 방어

- 8/4 평가 하네스에 "카탈로그 밖 소재" 케이스를 추가한다: 동백꽃 scatter(무언 대체 → 경고
  발화 확인), 페이즐리 lattice(모티프 없는 plan → 피커 사이드카 발화 확인). S3b가 이미
  페이즐리 케이스라 판정 기준에 경고/사이드카 항목만 더하면 된다.
- 유닛: 임계 미만 대체 경고, 어휘 확장 subject 추출.

## 범위 제외

- LLM이 소재를 더 잘 "그리게" 만드는 것(모티프 자체 생성 품질)은 다루지 않는다 — 소재는
  카탈로그·Recraft의 몫이고, 이 플랜은 공백을 정직하게 알리고 채우는 데까지다.

## 검증

- `uv run pytest` 통과 (경고·어휘 유닛 + 평가 하네스 케이스).
- Aside 재현: 동백꽃 scatter → 디자인 생성 + 노랑 경고 표시, 페이즐리 lattice → 패널 자동
  확장 + '페이즐리' 검색어 채움 + 스낵바 (D3b 재판정).
- Recraft 보강 실행 시: 실 호출 건수를 사전 합의한 수로 제한하고 승인 게이트 통과 후
  같은 프롬프트에서 요청 소재가 grounding 1순위로 잡히는지 확인.
