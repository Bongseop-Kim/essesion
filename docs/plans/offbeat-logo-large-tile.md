# 큰 타일 템플릿 — 작은 로고 엇박자 배치

스토어 `/design` 템플릿의 작은 로고(무늬 속 반복 로고)를 세로·가로 일직선 없이 엇박자로 놓기 위해,
템플릿별로 타일을 키우는(`tile_mm` > 48) 기능을 시드에 넣고 템플릿을 하나씩 옮긴다. 엔진·API 계약은
바꾸지 않는다. 2026-10-17 사용자 원칙("명확한 지시가 없으면 엇박자, 일정한 배치는 그 디자인의 특징일
때만, 체크는 예외")에서 나왔고, 첫 대상은 사용자가 고른 「핀 스트라이프와 세 고리」다.

## 왜 필요한가

- **구조적 한계(실측)**: 무늬는 타일 한 장을 복제한 것이라 타일 안 모든 자리가 1타일마다 같은 열·행에
  돌아온다. 카드 넥타이 폭 ≈ 2.35타일, 높이 ≈ 3.3타일이라 같은 열이 카드에서 3~4번 보인다. 밀도
  규칙(폭당 로고 2~3개)을 지키면 타일당 로고가 2~4개뿐이라 열이 2~4개밖에 없다.
- **하프드롭도 일직선**: `diagonal_pair`·`half_row`는 두 행마다 같은 열로 돌아온다. 사용자가 세리프 R과
  마름모 도트·가로 바와 날개 엠블럼·핀 스트라이프와 세 고리 카드에 빨간 세로선을 그어 짚었다
  (2026-10-17, 데스크톱 스크린샷 11.19.33·11.19.57·11.20.13).
- **위상 탐색 결과**: 2026-10-17 핀 스트라이프에서 줄 사이 레인 위 경로 위상을 격자 탐색했다(타일당
  4자리). 세로 열·가로 행 정렬이 가장 적은 해가 (0,0)·(¼,¼)·(½,½)·(¾,¾) — `\` 대각 일직선이었다.
  타일 크기를 그대로 두면 규칙성을 다른 방향으로 옮길 뿐이다.
- 엇박은 제작에도 유리하다 — 정렬된 배치는 재단 각도·반복 경계 오차가 그대로 드러난다(사용자 의견).

## 범위 밖

- 엔진(`worker.engine`)·API·프론트 코드 변경. 이미 `tile_mm`을 그대로 나르는 경로를 쓴다(아래 근거).
- 체크(윈도페인·다이아 체크·마름모 격자)처럼 칸에 묶인 로고, 배치형(panel) 템플릿.
- admin 저작 경로(`apps/api/src/api/domains/admin/authoring.py:344`·`:845`의 `tile_mm` 48 고정).

## 실행 조건

- 템플릿 시드 코드만 바뀌므로 언제든 실행 가능하다. 로컬 DB·서버(store :3000, api :8000)가 떠 있어야
  카드 확인을 할 수 있다.
- **실행하지 말 것**: 2단계(핀 스트라이프)에서 사용자가 결과를 받아들이지 않으면 3단계(나머지 템플릿)로
  넘어가지 않는다. 받아들인 구성을 기준으로 삼는다.

## 근거 — `tile_mm`이 이미 끝까지 흐른다

- 컴파일러가 `tile_mm`을 받는다 — `apps/worker/src/worker/design_plan/compiler.py:302`(기본 48,
  `:18`). 비율(`period_ratio`·`size_ratio`·`spacing_ratio`)은 모두 타일 기준이다.
- 스토어는 SVG 루트 `width="Nmm"`으로 반복 배율 N/48을 읽는다 —
  `apps/store/src/features/design/model/svg-preview.ts:30`, `packages/shared/src/components/tie-canvas.tsx:22`.
- 실사 목업도 intent의 `tile_mm`으로 비례한다 — `apps/worker/src/worker/render/photoreal.py:190`.
- 템플릿으로 시작한 세션은 run의 intent를 그대로 복원한다(재컴파일 없음) —
  `apps/api/src/api/domains/design/examples.py:199`.
- 사용자 배율 patch는 `tile_mm` [12, 192]로 누적 클램프 — `apps/worker/src/worker/engine/patch.py:49`.
  96에서 시작하면 키우기는 2배까지만 된다(허용).

## 절차

1. **시드에 타일 배율 필드** — `apps/worker/scripts/seed_design_examples.py:52` `CuratedExample`에
   `tile_scale: float = 1.0`을 더하고, `_compose_run`(`:1150`)이 `compile_design_plan_v3(…, tile_mm=48 ×
   tile_scale)`로 넘긴다(`:1163`). 기본 1.0이면 기존 템플릿 바이트가 그대로다. 근거: 위 경로가 이미
   `tile_mm`을 나른다.
2. **핀 스트라이프 스파이크** — `PIN_STRIPE_RINGS_PLAN`(`seed_design_examples.py:79` 부근)을
   `tile_scale=2`로 옮긴다.
   1. 먼저 겉모습 보존: 줄 주기 k=2→k=4(`period_ratio` 0.35355339→0.1767767, 밴드 비율은 주기 기준이라
      그대로), 고리 `size_ratio` 0.14→0.07. 카드가 지금(2×2)과 같아 보이는지 확인한다.
   2. 그다음 엇박 배치: 큰 타일 안 틈 4줄에 고리를 불규칙 위상으로 흩는다. 레인은 바탕색 밴드 스트라이프
      (`host_stripe_index`/`host_band_index`, 이미 쓰는 방식 — 같은 파일 `SPRIG_STRIPE_PLAN`)로 만든다.
      제약: 레이어 ≤5·모티프 ≤2·밴드 ≤4(스킬 "엔진 제약"). 레인 경로 한 레이어는 타일당 레인 한 줄만
      채운다(2026-10-17 확인) — 핀 줄 + 레인 스트라이프 + 경로 3레이어가 상한이다.
   3. 배치 후보는 점 좌표를 뽑아 정렬 지표(쌍별 최소 |Δx|·|Δy|·|Δ(x−y)|, 열·행 최대 공백)로 먼저 거르고
      카드로 본다. 타일당 자리가 모자라 밀도가 떨어지면 그 사실을 사용자에게 보이고 결정을 받는다.
3. **나머지 반복 로고 템플릿** — 사용자가 2단계를 받아들인 뒤 하나씩: 세리프 R과 마름모 도트, 가로 바와
   날개 엠블럼, 물결선과 물결 원 엠블럼, 로고 하프드롭과 점. 줄·물결에 묶이지 않은 로고는 플랜의
   `scatter` `poisson`(`apps/worker/src/worker/design_plan/schema.py:110`, 결정론 seed)으로 불규칙하게
   흩을 수 있다 — 다른 모티프와 겹침은 보장되지 않으니 카드로 확인한다.
4. **명세·스킬** — `docs/api-spec/worker-engine.md:36`의 `tile_mm` 문단에 "시드 템플릿은 엇박 배치를 위해
   48보다 큰 `tile_mm`으로 시작할 수 있다"를 한 줄 더한다. `.claude/skills/tie-template/SKILL.md`의
   "엇박의 구조적 한계" 항목을 결과로 고친다.

## 검증

- `uv run pytest apps/worker/tests/test_seed_design_examples.py`
- `uv run python apps/worker/scripts/seed_design_examples.py` — 출력 warnings가 모두 `[]`.
- `uv run python .claude/skills/tie-template/scripts/check_emblems.py` — 로고 subject 확인.
- 스토어 `/design` 카드 스크린샷(deviceScaleFactor=2)에서 작은 로고가 세로·가로로 일직선을 이루지 않는지,
  큰 로고·줄과 겹치지 않는지 본다. 상세(실사 컷)도 로그인해 확인한다 — 반복 주기가 길어진 것이 실사에서
  어색하지 않은지.

## 되돌리는 법

`tile_scale`을 1.0으로 돌리고 플랜 비율을 원래 값으로 되돌린 뒤 시드를 다시 돌린다(템플릿은 시드 코드가
정본이라 DB 손작업이 필요 없다). 신호: 카드 렌더가 눈에 띄게 느려지거나(래스터 픽셀이 타일² 비례로
4배), 실사 컷에서 반복이 어색하다는 사용자 판단.

## 기각한 대안

- **타일 그대로 두고 위상만 조정** — 2026-10-17 탐색에서 규칙성이 다른 방향으로 옮겨질 뿐이었다.
- **로고를 줄 무시하고 poisson 산개(핀 스트라이프)** — 고리가 핀 줄 위에 올라간다. 줄 없는 템플릿에서만 쓴다.
- **엔진에 레인별 위상·비주기 배치 추가** — 계약 변경이 크다. 큰 타일로 부족하다는 실측이 나오면 재론한다.

실패 모드: 타일을 키워 반복 주기만 늘고 배치는 여전히 규칙적(하프드롭·대각 일직선)으로 남는 것, 또는
레이어 상한 때문에 자리가 모자라 밀도가 떨어진 것을 "엇박 완료"로 보고하는 것.
